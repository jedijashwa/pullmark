Problemen oplossen

De paar dingen die mis kunnen gaan, wat de meldingen van PullMark betekenen, en het ontwerp achter de stillere manieren van falen — de meeste "fouten" hier zijn de app die bewust weigert je werk kwijt te raken.

GitHub-toegang: hoe PullMark verbindt, en hoe je het repareert

PullMark leent de GitHub-credentials die je eigen tools al hebben — het heeft geen eigen login en bewaart nooit een geheim. Instellingen → Algemeen → GitHub toont of er verbinding is, als wie, en via welke bron; Stel in… loodst een nieuwe machine door het verbinden, en Controleer opnieuw pikt een reparatie meteen op — na gh auth login, zonder herstart.

Lees je dit op de Mac waar PullMark (0.36+) is geïnstalleerd? Open nu de verbindingsrij.

De credentialbronnen, in de volgorde waarin PullMark ze probeert:

  1. Het token van de GitHub CLI: gh auth token moet er een printen. Zo niet, dan brew install gh && gh auth login — de aanbevolen route: dat token heeft gegarandeerd goede scopes, handelt SSO af via de browserflow, en ververst zichzelf.
  2. Anders git credential fill — wat git zelf gebruikt voor github.com (de macOS-sleutelhanger, Git Credential Manager, een token bewaard door een oude HTTPS-push).

De kleine lettertjes, voor tokens die maar half werken: klassieke tokens hebben de scope repo nodig (en read:org voor teamnamen in organisaties); fine-grained tokens zijn gebonden aan één resource owner — publieke repo's en de privérepo's van die eigenaar werken, al het andere wordt geweigerd; organisaties met SSO vereisen dat het token per organisatie is geautoriseerd; en handmatig aangemaakte tokens verlopen — de rij in Instellingen is de plek waar "gisteren werkte het nog" wordt gediagnosticeerd.

GitHub: "bestaat mogelijk niet op die ref… of het is een privérepository"

"Kon … niet openen. Het bestaat mogelijk niet op die ref, of het is een privérepository waar je GitHub-credentials geen toegang toe hebben." GitHubs API meldt privé-zonder-toegang en bestaat-niet identiek, dus PullMark kan je niet vertellen welke van de twee het is. Zou de repo moeten werken, dan is het bijna altijd authenticatie — zie GitHub-toegang hierboven, of open Instellingen → Algemeen → GitHub en klik op Stel in….

Gatekeeper wil de app niet openen

Releases zijn ondertekend met een Developer ID en genotariseerd door Apple, dus een normale download toont geen waarschuwing. Heb je zelf vanaf de broncode gebouwd (make app), dan is de app ad-hoc ondertekend: rechtsklik → Open → Open, of sta hem toe onder Systeeminstellingen → Privacy & beveiliging.

Quick Look-previews renderen niet meer

Een Homebrew-upgrade vervangt de app-bundle, wat de registratie van de Quick Look-extensie geruisloos kan laten vallen. PullMark registreert haar bij elke start opnieuw — start de app dus gewoon één keer. Tonen previews daarna nog steeds ruwe tekst, controleer dan of Instellingen → Algemeen → "Quick Look-previews" op Gerenderd staat.

"PullMark is niet langer je standaard-Markdown-app"

Zelfde oorzaak: een upgrade verving de bundle en macOS liet de .md-koppeling vallen. Maak weer standaard in de banner claimt haar terug; Instellingen → Algemeen ook.

"… is veranderd terwijl je bezig was met het bewerken van dit blok — er is niets bewaard"

Het bestand veranderde op schijf (een andere editor, een agent, een git-operatie) tussen het openen van de blokeditor en het opslaan. PullMark weigert te splitsen in regels die zijn verschoven — er gaat niets verloren behalve die ene bewerking, en het blok opnieuw openen toont de actuele tekst. Dezelfde bescherming geldt voor commits: vergelijken met een ref waar het bestand niet bestaat wordt gewoon gemeld, in plaats van een lege diff te tonen.

Gedimde rijen: mappen en recente items die "er niet zijn"

Een Locatie met een vraagtekenbadge, of een grijs recent item, betekent dat het pad op dit moment niet oplost — een niet-geactiveerd volume, een gewisselde git-branch, een verwijderde worktree. Rijen dimmen met opzet in plaats van te verdwijnen: ze herleven automatisch wanneer het pad terugkeert. Klikken op een dood recent item biedt Verwijder uit Recent of Behoud.

Pull requests: banners en openstaande comments

  • "Deze pull request is bijgewerkt op GitHub." — de branch is verplaatst sinds je hem laadde. Verversen is één klik en je conceptcomments blijven bewaard; PullMark herlaadt nooit vanzelf onder een lopende review.
  • "Reviewcomments konden niet worden geladen…" — de diff zou zich anders voordoen als een PR zonder comments; Probeer opnieuw haalt ze opnieuw op.
  • "Kon N pending comment(s) niet naar GitHub uploaden… lokaal bewaard voor een nieuwe poging." — comments die offline zijn geschreven (of door een API-hapering) komen per PR-head op schijf in de wachtrij en uploaden zodra het kan. Er valt niets weg.
  • "… gecommit, maar de push is mislukt" — de commit staat veilig in je lokale geschiedenis; alleen de push moet opnieuw.

Updates

Werk nu bij in de banner draait de brew-upgrade (of een geverifieerde in-place-installatie voor DMG-installaties) en herstart. Mislukt dat, dan toont de banner het exacte commando brew upgrade --cask pullmark met een kopieerknop — het in een terminal draaien doet hetzelfde. Developmentbuilds controleren niet op updates.

Het pullmark-commando

  • "no such file or folder" — het commando controleert elk pad voordat het iets opent; één typefout breekt de hele open af (exitcode 1), zodat scripts luid falen.
  • Command not found — zie het commando installeren.
  • "Couldn't install the command" — de installer in Instellingen heeft toestemming nodig om naar /usr/local/bin te schrijven; annuleer en probeer opnieuw als je de prompt hebt weggeklikt.
