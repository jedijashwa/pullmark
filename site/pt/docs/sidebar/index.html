A barra lateral

Quatro seções, organizadas pelo que as coisas significam, não pela origem: o que você tem aberto, os lugares pelos quais navega, os pull requests que está revisando e por onde você já passou.

Open Files

O conjunto de trabalho (arquivos abertos): cada documento que você abriu explicitamente — pelo Finder, arrastar & soltar, ⌘O, a linha de comando, ou mantendo um arquivo de um Location. Plano, reordenável por arrasto, cada linha removível com o ✕ que aparece ao passar o mouse (ou ⌫ na linha selecionada). Clique com o botão direito no cabeçalho da seção para Close All (fechar tudo).

Prévias

Um clique num arquivo dentro de um Location e ele renderiza imediatamente — e aparece em Open Files como prévia: uma entrada em itálico, sempre a última da seção. Clique em outro arquivo e a entrada de prévia é substituída, então navegar por uma árvore grande nunca acumula linhas. É a mesma ideia das abas de prévia do VS Code ou do editor temporário do Xcode, vestindo o mesmo itálico.

Uma prévia vira uma entrada normal, fixada, quando você demonstra qualquer compromisso além da leitura:

  • Clique duplo no arquivo na árvore, ou na própria entrada em itálico
  • Começar a editar — entrar no Edit Mode (modo de edição) ou salvar a edição de um bloco a fixa
  • Keep Open (manter aberto) no menu do botão direito

Interações de leitura — blame, histórico de linhas, inspecionar uma imagem ou diagrama — deliberadamente nunca promovem uma prévia. Se você preferir que cada clique abra arquivos por completo, mude Clicking files in Locations nos Ajustes.

Repositórios remotos fazem prévia do mesmo jeito, no mesmo lugar. Navegar pela árvore de um repositório do GitHub, ou seguir links dentro de um documento remoto, coloca a mesma entrada única em itálico em Open Files — com um ícone de livro e uma segunda linha owner/repo @ ref, já que o arquivo não está no seu Mac. Só existe uma prévia por janela, local ou remota: pré-visualizar qualquer coisa substitui o que você estava pré-visualizando antes. Manter um doc remoto (clique duplo ou Keep Open) é o que o arquiva com seu repositório — ele se move para a lista fixada do repositório sob Locations. ⌘K abre já fixando, porque colar uma URL é intenção explícita.

Qualquer linha de Open Files que more dentro de um Location aberto ganha Reveal in Location (revelar no Location) no menu do botão direito — o salto de volta de “o que estou lendo” para “onde isso mora”.

Locations

Raízes navegáveis (locais), onde quer que morem. Dois tipos dividem a seção, distinguidos pelo ícone:

LinhaSignificado
📁 ícone de pastaUma pasta local — seus arquivos Markdown como árvore (ou lista plana; botão direito → View as List). Vigiada por mudanças.
📕 ícone de livroUm repositório do GitHub aberto para navegação — buscado pela API, nada gravado no disco.

Uma pasta local que é um checkout git ganha um chip de branch (glifo de branch + nome); se o remoto dela está no GitHub, uma pequena marca de livro fechado aparece também — passe o mouse para ver qual repositório. Clicar no chip de branch abre o menu de branches e worktrees:

  • Worktrees — cada worktree do repositório, com uma marca na que esta linha é; escolha outra para abri-la como Location próprio. Worktrees nunca sofrem checkout nem troca pelo PullMark — ele abre a pasta que já está lá.
  • View Branch from GitHub (ver branch do GitHub) — leia os arquivos de outra branch remotamente, sem tocar no seu checkout. Uma branch que já tem worktree local pula para a worktree — local ganha do remoto.
  • Open on GitHub (abrir no GitHub) — o repositório (nesta branch) no seu navegador.

Num repositório remoto (ícone de livro), o mesmo chip lista branches: Switch To (trocar para) re-fixa a sessão em outra branch, e segurar ⌥ oferece Open Branch Separately (abrir branch separadamente) para leitura lado a lado. Browse Repo Files… (navegar pelos arquivos do repositório) carrega a árvore Markdown inteira. Os docs mantidos do repositório ficam acima da árvore, para nunca se afogarem num repositório grande; um doc mantido que está visível na árvore é simplesmente representado ali. (Um doc que você está apenas pré-visualizando aparece em Open Files, não aqui.)

Uma pasta cujo caminho para de resolver (um volume desmontado, uma worktree apagada) escurece com um selo de interrogação em vez de sumir — ela revive sozinha quando o caminho volta.

Pull Requests

Cada PR aberto é um grupo: a linha da visão geral (ícone de status + contagem de Markdown alterado), depois seus arquivos Markdown alterados — um balão de fala com um número marca arquivos com threads de revisão não resolvidas. Abaixo dos seus PRs abertos, Review Requests (solicitações de revisão) reúne PRs esperando pela sua revisão, com um contador de não lidos que permanece visível mesmo recolhido (ocultável nos Ajustes, e filtrável para só PRs que tocam Markdown).

Ícones de status nas linhas de PR:

StatusÍcone
Rascunhosetas de pull request, cinza
Abertosetas de pull request, verde
Mergedsetas de merge, roxo
Fechado✕ num círculo, vermelho
Indisponívellixeira, cinza — o PR (ou seu acesso) foi embora

Marcadores por arquivo dentro de um PR: círculo + (verde) para adicionado, círculo − (vermelho) para removido, círculo → para renomeado, círculo com lápis para modificado.

Recents

Arquivos, pastas e pull requests abertos recentemente (recentes) que não estão visíveis acima. Entradas de PR carregam seu ícone de status ao vivo; um recente cujo arquivo sumiu escurece (selo de relógio) em vez de desaparecer, e revive quando o caminho volta — feito para trocas de branch e volumes desmontados. Clique com o botão direito no cabeçalho para Clear Recents (limpar recentes).

Removendo coisas

Passe o mouse sobre qualquer linha de nível superior para o ✕ — ele remove a linha da barra lateral, nunca nada do disco ou do GitHub. ⌫ na linha selecionada faz o mesmo. Arquivos dentro da árvore de um Location não têm ✕: eles são conteúdo de um lugar, não itens da barra lateral.

Glossário de ícones

ÍconeSignificado
DocumentoUm arquivo Markdown
Documento, nome em itálicoA prévia — substituída pelo seu próximo clique
PastaUma pasta ou diretório local
Pasta + ?Pasta não encontrada agora — escurecida, vai reviver
Documento + relógioUm arquivo recente que sumiu
Livro fechadoUm repositório do GitHub (como ícone de linha: navegado remotamente; como pequena marca no fim: esta pasta local é um checkout de um)
Glifo de branch + nomeO chip de branch — clique para branches e worktrees
Setas de pull requestUm pull request
BandejaReview Requests — PRs aguardando a sua revisão
Balão de fala + númeroNum arquivo de PR: comentários de revisão não resolvidos. Numa linha de Open Files: notas de margem ainda no documento
Ponto colorido (borda esquerda)Uma solicitação de revisão não lida
✕ num círculo (ao passar o mouse)Remover da barra lateral / dispensar a prévia

O glifo de branch aparece apenas em refs git de verdade (chips, nunca como ícone de pasta) — pasta é pasta, repositório é livro, branch é branch.
