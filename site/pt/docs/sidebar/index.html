A barra lateral

Seções organizadas pelo que as coisas significam, não pela origem: o que você tem aberto, os lugares que você guarda, os lugares pelos quais navega, os pull requests e issues que envolvem você e por onde você já passou.

Arquivos Abertos

O conjunto de trabalho: cada documento que você abriu explicitamente — pelo Finder, arrastar & soltar, ⌘O, a linha de comando, ou mantendo um arquivo de uma Localização. Plano, reordenável por arrasto, cada linha removível com o ✕ que aparece ao passar o mouse (ou ⌫ na linha selecionada). Clique com o botão direito no cabeçalho da seção para Fechar Tudo.

Prévias

Um clique num arquivo dentro de uma Localização e ele renderiza imediatamente — e aparece em Arquivos Abertos como prévia: uma entrada em itálico, sempre a última da seção. Clique em outro arquivo e a entrada de prévia é substituída, então navegar por uma árvore grande nunca acumula linhas. É a mesma ideia das abas de prévia do VS Code ou do editor temporário do Xcode, vestindo o mesmo itálico.

Uma prévia vira uma entrada normal, fixada, quando você demonstra qualquer compromisso além da leitura:

  • Clique duplo no arquivo na árvore, ou na própria entrada em itálico
  • Começar a editar — entrar no Modo de Edição ou salvar a edição de um bloco a fixa
  • Manter Aberto no menu do botão direito

Interações de leitura — blame, histórico de linhas, inspecionar uma imagem ou diagrama — deliberadamente nunca promovem uma prévia. Se você preferir que cada clique abra arquivos por completo, mude Clicar em arquivos em Localizações nos Ajustes.

Repositórios remotos fazem prévia do mesmo jeito, no mesmo lugar. Navegar pela árvore de um repositório do GitHub, ou seguir links dentro de um documento remoto, coloca a mesma entrada única em itálico em Arquivos Abertos — com um ícone de livro e uma segunda linha owner/repo @ ref, já que o arquivo não está no seu Mac. Só existe uma prévia por janela, local ou remota: pré-visualizar qualquer coisa substitui o que você estava pré-visualizando antes. Manter um doc remoto (clique duplo ou Manter Aberto) é o que o arquiva com seu repositório — ele se move para a lista fixada do repositório sob Localizações. ⌘K abre já fixando, porque colar uma URL é intenção explícita.

Qualquer linha de Arquivos Abertos que more dentro de uma Localização aberta ganha Mostrar na Localização no menu do botão direito — o salto de volta de “o que estou lendo” para “onde isso mora”.

Fixados

As pastas e arquivos aos quais você sempre volta, acima de Localizações do jeito que o Finder mantém os Favoritos acima de tudo o mais. Clique com o botão direito numa pasta ou arquivo em qualquer árvore e escolha Fixar…: uma pasta vira sua própria raiz com sua própria árvore, um arquivo vira uma linha de marcador que faz prévia ao clicar, e a nova entrada aparece no fim da seção já em modo de renomear. Uma raiz de Localização ganha Fixar (ela se move para cá) e uma raiz fixada ganha Desafixar (ela se move para o fim de Localizações, mantendo o nome).

Renomear funciona do jeito do Finder: escolha Renomear… ou pressione Return na linha selecionada, digite o novo nome e confirme com Return, um clique em qualquer outro lugar, ou saindo do campo; Esc cancela; um campo deixado em branco volta ao nome real. Uma entrada renomeada mostra o caminho verdadeiro em texto pequeno abaixo do nome, o mesmo vale para qualquer par de raízes que compartilhem um nome, para que duas pastas chamadas docs nunca pareçam iguais. Entradas fixadas são uma preferência, não parte da sessão: elas voltam a cada abertura, não importa o que Reabrir a sessão anterior diga.

Localizações

Raízes navegáveis, onde quer que morem. Dois tipos dividem a seção, distinguidos pelo ícone:

LinhaSignificado
📁 ícone de pastaUma pasta local — seus arquivos Markdown como árvore (ou lista plana; botão direito → Ver como Lista). Vigiada por mudanças.
📕 ícone de livroUm repositório do GitHub aberto para navegação — buscado pela API, nada gravado no disco.

Uma pasta local que é um checkout git ganha um chip de branch (glifo de branch + nome); se o remoto dela está no GitHub, uma pequena marca de livro fechado aparece também — passe o mouse para ver qual repositório. Clicar no chip de branch abre o menu de branches e worktrees:

  • Worktrees — cada worktree do repositório, com uma marca na que esta linha é; escolha outra para abri-la como Localização própria. Worktrees nunca sofrem checkout nem troca pelo PullMark — ele abre a pasta que já está lá.
  • Ver Branch do GitHub — leia os arquivos de outra branch remotamente, sem tocar no seu checkout. Uma branch que já tem worktree local pula para a worktree — local ganha do remoto.
  • Abrir no GitHub — o repositório (nesta branch) no seu navegador.

Num repositório remoto (ícone de livro), o mesmo chip lista branches: Trocar Para re-fixa a sessão em outra branch, e segurar ⌥ oferece Abrir a Branch Separadamente para leitura lado a lado. Navegar pelos Arquivos do Repositório… carrega a árvore Markdown inteira. Os docs mantidos do repositório ficam acima da árvore, para nunca se afogarem num repositório grande; um doc mantido que está visível na árvore é simplesmente representado ali. (Um doc que você está apenas pré-visualizando aparece em Arquivos Abertos, não aqui.)

Uma pasta cujo caminho para de resolver (um volume desmontado, uma worktree apagada) escurece com um selo de interrogação em vez de sumir — ela revive sozinha quando o caminho volta.

Pull Requests

Cada PR aberto é um grupo: a linha da visão geral (ícone de status + contagem de Markdown alterado), depois seus arquivos Markdown alterados — um balão de fala com um número marca arquivos com threads de revisão não resolvidas. Abaixo dos seus PRs abertos vêm os pull requests que envolvem você, em grupos: Solicitações de Revisão, Criados, Atribuídos e Participando (você comentou, revisou, ou foi mencionado). Grupos vazios ficam ocultos, rascunhos dizem · rascunho, e uma linha explica por que está ali (· atribuído, · mencionado) quando o grupo sozinho não deixa claro. Cada grupo carrega os 30 atualizados mais recentemente e termina em Mostrar mais…. Contadores de não lidos permanecem visíveis em cabeçalhos recolhidos; a coisa toda é opcional nos Ajustes, e filtrável para PRs que tocam Markdown.

Siga um repositório para ver tudo o que está aberto nele, dos mais novos aos mais antigos: Seguir repositório… no cabeçalho da seção oferece os repositórios que você já tem abertos, ou aceita owner/repo digitado. Um repositório seguido é seu próprio grupo com sua própria regra de não lidos — clique com o botão direito nele para Tudo, Só os meus ou Nenhum, e para Deixar de seguir. Qualquer linha de PR ou issue pode sobrepor essa regra a partir do próprio menu de botão direito.

Prefere uma lista só? Agrupar trabalho do GitHub por Participação mescla esta seção e Issues numa única seção GitHub, com grupos misturando os dois tipos e um glifo por linha.

Ícones de status nas linhas de PR:

StatusÍcone
Rascunhosetas de pull request, cinza
Abertosetas de pull request, verde
Mescladosetas de merge, roxo
Fechado✕ num círculo, vermelho
Indisponívellixeira, cinza — o PR (ou seu acesso) foi embora

Marcadores por arquivo dentro de um PR: círculo + (verde) para adicionado, círculo − (vermelho) para removido, círculo → para renomeado, círculo com lápis para modificado.

Issues

A mesma ideia para issues — Criados, Atribuídos, Participando e as issues dos repositórios seguidos — porque o documento que pedem para você revisar muitas vezes é uma issue, não um pull request. Clique numa e ela abre como um documento: o corpo renderizado, suas labels, a linha do tempo de comentários com reações, e uma caixa de comentário no fim. Comente, reaja, e edite ou exclua seus próprios comentários sem sair do app. Uma issue aberta fica no topo da seção como uma única linha, entra em Recentes e no Abrir Rapidamente (⌘K), e volta com a sessão.

Recentes

Arquivos, pastas e pull requests abertos recentemente que não estão visíveis acima. Entradas de PR carregam seu ícone de status ao vivo; um recente cujo arquivo sumiu escurece (selo de relógio) em vez de desaparecer, e revive quando o caminho volta — feito para trocas de branch e volumes desmontados. Clique com o botão direito no cabeçalho para Limpar Recentes.

Removendo coisas

Passe o mouse sobre qualquer linha de nível superior para o ✕ — ele remove a linha da barra lateral, nunca nada do disco ou do GitHub. ⌫ na linha selecionada faz o mesmo. Arquivos dentro da árvore de uma Localização não têm ✕: eles são conteúdo de um lugar, não itens da barra lateral.

Glossário de ícones

ÍconeSignificado
DocumentoUm arquivo Markdown
Documento, nome em itálicoA prévia — substituída pelo seu próximo clique
PastaUma pasta ou diretório local
Pasta + ?Pasta não encontrada agora — escurecida, vai reviver
Documento + relógioUm arquivo recente que sumiu
Livro fechadoUm repositório do GitHub (como ícone de linha: navegado remotamente; como pequena marca no fim: esta pasta local é um checkout de um)
Glifo de branch + nomeO chip de branch — clique para branches e worktrees
Setas de pull requestUm pull request
Círculo com um pontoUma issue
Bandeja · círculo com lápis · círculo de pessoa · dois balõesOs grupos: Solicitações de Revisão · Criados · Atribuídos · Participando
Caminho pequeno abaixo de um nomeO local real de uma raiz fixada ou renomeada (também mostrado quando duas raízes compartilham um nome)
Balão de fala + númeroNum arquivo de PR: comentários de revisão não resolvidos. Numa linha de Arquivos Abertos: notas de margem ainda no documento
Ponto colorido (borda esquerda)Um pull request ou issue não lido
✕ num círculo (ao passar o mouse)Remover da barra lateral / dispensar a prévia

O glifo de branch aparece apenas em refs git de verdade (chips, nunca como ícone de pasta) — pasta é pasta, repositório é livro, branch é branch.
