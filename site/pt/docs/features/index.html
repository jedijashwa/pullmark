Recursos

O tour, agrupado pelo que você está fazendo: ler, revisar, navegar pelo GitHub, editar e tirar documentos de volta. O PullMark deliberadamente não é um cliente de revisão completo — ele mostra o Markdown de uma mudança; suas ferramentas de sempre continuam certas para o código.

Leitura

  • Renderização fiel ao GitHub — tabelas, listas de tarefas, notas de rodapé, alertas, <details> recolhíveis, realce de sintaxe, diagramas Mermaid e matemática KaTeX ($…$ / $$…$$), tudo offline. Um parágrafo contendo só [toc] vira um sumário com links; ==destaque==, ~sub~ e ^sup^ também renderizam.
  • Clique para inspecionar — imagens, diagramas e fórmulas de bloco abrem num overlay de pan e zoom; Salvar Como… e Compartilhar exportam exatamente o que você está inspecionando (diagramas como SVG de verdade).
  • Arquivos vivos — documentos re-renderizam ao serem salvos em qualquer editor; imagens e links relativos resolvem, e clicar num link para outro arquivo Markdown o abre no lugar (como prévia quando ele mora numa Localização aberta).
  • Navegação — a barra lateral de estrutura (⌥⌘O), busca na página com ⌘F, busca em todos os arquivos da barra lateral com ⇧⌘F, e o Abrir Rapidamente com ⌘K para títulos, arquivos, PRs e recentes — ou cole nele um caminho ou uma URL do GitHub.
  • Blame à altura da leitura — uma régua discreta de autoria: um avatar por sequência de blocos, passe o mouse para ver o commit, clique para o histórico das linhas. A API de blame do GitHub quando o arquivo mora no GitHub, git blame puro nos demais casos.
  • Conforto de leitura — temas, largura do conteúdo, números de linha (Ajustes), zoom no estilo dos navegadores, claro/escuro, tela cheia e posições de leitura lembradas por documento.

Revisão de pull requests

  • Diffs renderizados — blocos adicionados, removidos e alterados destacados na página renderizada, diffs palavra por palavra quando a edição é pequena o bastante para fazer sentido, em linha ou lado a lado (⌥⌘L), mais o Diff do Código-Fonte cru (⌘2) e o Resultado final (⌘3). Parágrafos movidos ganham um chip discreto de “movido” em vez de ruído vermelho-mais-verde.
  • Threads de revisão no lugar — comentários existentes aparecem sob os blocos que discutem; passe o mouse sobre um bloco para Comment Now (comentar agora), Add to Review (adicionar à revisão) ou Insert Suggestion (inserir sugestão) — e o lápis edita o bloco como sugestão. Revisões são enviadas com veredito, ou salvas no GitHub como revisão pendente.
  • Onde o PR está — o cabeçalho da visão geral mostra a decisão da revisão (aprovado, alterações solicitadas, revisão necessária), o veredito de cada revisor como avatares com selos, com os revisores aguardados ao lado, e uma cápsula de verificações de CI que abre a lista completa — durações, marcas de obrigatoriedade e um link para os logs de cada verificação. Tudo se atualiza silenciosamente a cada minuto.
  • A conversa, legível — uma linha do tempo cronológica na visão geral: comentários e vereditos de revisão em ordem, os comentários inline de cada revisão aninhados sob seu resumo, com o arquivo que discutem nomeado no cartão. Reações, edições e exclusões dos seus próprios comentários, e a caixa de comentário no pé da linha do tempo. Ativa para todos (Ajustes ▸ Geral ▸ Revisão esconde as threads).
  • Sempre atual — PRs abertos são checados a cada minuto; um banner oferece atualizar quando a branch avança, e seus rascunhos de comentário sobrevivem. Comentários escritos offline entram na fila e sobem quando podem.
  • Solicitações de revisão — PRs aguardando a sua revisão, na barra lateral com contadores de não lidos. Imagens de PR e links relativos ao repositório resolvem no commit do PR.

GitHub, sem o navegador

  • Links de Markdown abrem no app — clique num link github.com/…/blob/… e o PullMark o renderiza (o primeiro clique pergunta; ⌘-clique inverte seu padrão). Uma barra de procedência fixa owner/repo @ ref · caminho com um caminho de volta ao GitHub.
  • Navegue por repositórios inteiros — carregue a árvore Markdown de um repositório em Localizações, troque de branch, compare com outras branches, veja o blame — repositórios privados usam as credenciais que os PRs já usam, e nada do que é buscado toca o disco.
  • Branches e worktrees — checkouts locais vestem um chip de branch; seu menu abre worktrees como Localizações próprias e lê outras branches remotamente. Local sempre ganha do remoto quando uma worktree já tem a branch.

Edição e commits

  • Edite no lugar — o lápis de um bloco (ou ⌘E para o documento inteiro) transforma blocos em editores dentro da página renderizada; ⌘↩ salva, Esc cancela. Os salvamentos são protegidos contra o arquivo mudar por baixo, e versionados para o Reverter Última Edição.
  • Commit de dentro do app — ⌃⌘K abre a folha de commit para o repositório do arquivo: escolha arquivos, escreva a mensagem, opcionalmente faça push, com uma proteção antes de commitar direto na main.

Comparação com o histórico

  • Qualquer arquivo, qualquer revisão — o botão Comparar da barra de ferramentas (o relógio com chevron) diffa o arquivo de trabalho contra qualquer um dos seus últimos 25 commits, ou qualquer branch local ou remota — renderizado, com as palavras alteradas em destaque, exatamente como um pull request. Um ponto discreto no botão significa que o arquivo tem mudanças não commitadas.
  • “O que eu acabei de mudar?” — um item de menu (Visualizar → Compare with Last Commit) ou um comando de shell (pullmark --diff arquivo.md, veja a CLI). O diff acompanha o arquivo enquanto ele continua mudando — veja as edições de um agente aterrissarem, destacadas, a cada salvamento.

Tirando documentos de volta

  • Exportação — PDF (uma página contínua) ou HTML totalmente autossuficiente; Compartilhar envia o documento para onde o macOS alcançar.
  • Cópia em dois sabores — ⌘C é texto rico para Docs/Slack; ⌥⌘C é o Markdown por trás.
  • Impressão — ⌘P, a 100% independentemente do zoom.
  • Quick Look — espaço no Finder pré-visualiza Markdown com a renderização do próprio PullMark.

Uma barra de ferramentas que é sua

Clique com o botão direito na barra de ferramentas — ou Visualizar → Personalizar Barra de Ferramentas… — para a paleta nativa de personalização: arraste para fora o que você nunca usa, reorganize o resto, adicione Flexible Space (espaço flexível). Cada tipo de visão mantém seu próprio arranjo, lembrado entre as aberturas: um arquivo local, um doc do GitHub, um arquivo de pull request e a visão geral do PR são barras separadas, e você personaliza cada uma enquanto está nela — do mesmo jeito que a janela de composição do Mail mantém sua própria barra.

Além do conjunto padrão, a paleta guarda itens que começam ocultos: um interruptor de Código-Fonte, Mais Zoom / Tamanho Real / Menos Zoom, o seletor de Largura do Conteúdo, Adicionar Nota de Margem (enquanto o recurso estiver ativo) e, para docs do GitHub, Compartilhar — a página github.com do documento, nunca um link cru — e Recarregar, que re-resolve uma branch para sua ponta atual e permanece desativado, com o motivo, para documentos abertos num commit específico. De fábrica, nada muda; a paleta guarda o resto. A barra de ferramentas lista os itens de cada visão.

Todo o resto

  • Janelas e abas — ⌘N abre uma janela independente; mescle em abas nativas. Aberturas externas chegam na janela da frente.
  • O comando pullmark — arquivos, pastas e worktrees de qualquer terminal. Veja Linha de comando.
  • Controle do app padrão — torne o PullMark o responsável por .md com um clique, e ele percebe se uma atualização derrubar o vínculo.
  • Atualizações embutidas — releases assinadas e notarizadas, com atualização em um clique e uma folha de Novidades.
  • Postura de privacidade — o conteúdo do GitHub é buscado pela API e mantido em memória, e documentos nunca são copiados para lugar nenhum. A página de privacidade conta a história completa.
