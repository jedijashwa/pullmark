Docs existem para ser diffados lidos.

O PullMark renderiza seu Markdown local do jeito que os leitores vão vê-lo — e mostra pull requests do GitHub carregados de documentação como diffs renderizados, com apenas as palavras alteradas em destaque. Comente, sugira e envie sua revisão sem nunca mais apertar os olhos diante de um paredão de prosa em +/−.

seu agente

Seu agente escreve planos.
Revise como se fossem de um colega.

Agentes produzem Markdown aos montes: planos de implementação, especificações, relatórios de pesquisa — documentos longos que precisam do seu julgamento antes que alguém aja sobre eles. Os jeitos que já existem de dar esse julgamento erram todos o alvo. O código-fonte cru num editor esconde o que o leitor veria, colar trechos num chat separa o feedback do lugar a que ele pertence, e commitar um rascunho de trabalho só para ganhar as caixas de comentário de um PR é pura cerimônia — nem todo documento pertence a um pull request.

As notas de margem colocam o feedback no próprio documento. Leia o rascunho renderizado, clique onde está errado e deixe uma nota assinada, ancorada naquele bloco. As notas são comentários HTML comuns, que ficam fora da página renderizada — assim, “resolva minhas notas no plano” é a entrega inteira: seu agente lê cada nota exatamente onde você a deixou. Sem commit, sem colar, sem pull request. Depois, veja a revisão chegar — o Compare (comparar) destaca as edições do agente palavra por palavra, ao vivo, a cada salvamento.

O ciclo completo — incluindo as instruções para entregar ao seu agente — está destrinchado na página de agentes. As notas de margem estão em beta e vêm ativadas por padrão; a documentação cobre a mecânica.

por quê

Prosa não é código.
Pare de revisar como se fosse.

Você conhece o momento: um paredão verde de quarenta linhas num diff de README e, em algum lugar lá dentro, a única frase que de fato mudou. Docs de design, registros de decisão, runbooks, definições de agentes — a cada semana, uma parte maior do que passa pela sua fila de revisão é prosa, e um diff do código-fonte da prosa esconde exatamente aquilo que você está ali para julgar.

O PullMark mostra a mudança do jeito que os leitores vão encontrá-la: renderizada, com apenas as palavras alteradas em destaque. Tabelas continuam tabelas, diagramas continuam diagramas, e uma edição de uma palavra é uma palavra destacada. Comente em qualquer bloco e o comentário cai exatamente nas linhas que o GitHub espera — aprove, solicite alterações ou deixe sugestões que o autor aplica com um clique.

“A sala de leitura ao lado da oficina.”
Nota

O PullMark deliberadamente não é um cliente de revisão completo. Ele mostra apenas os arquivos Markdown de um PR — para as partes de código de uma mudança, suas ferramentas de revisão de sempre continuam sendo o lugar certo.

revisão

A revisão de docs inteira, direto da página renderizada.

Alterne entre os layouts inline e lado a lado, desça ao Source Diff (o diff da fonte crua) ou visualize o Result (o resultado final) — tudo pela barra de ferramentas, que também leva você de arquivo em arquivo e de volta ao PR sem tocar na barra lateral. YAML front matter renderiza como uma tabela de metadados discreta, não um paredão de prosa em negrito — então docs carregados de configuração também diffam limpo. Um documento novo em folha lê como documento — uma única nota avisa que é tudo novo, em vez de tingir cada bloco de verde. Threads de revisão existentes aparecem sob os blocos que discutem. Passe o mouse sobre qualquer bloco, clique no balão e comente no bloco inteiro ou exatamente nas linhas que você escolher. Ao terminar, Approve (aprovar), Request Changes (solicitar alterações) ou Comment (comentar), direto da visão geral — com ou sem comentários de linha — e deixe também comentários no arquivo inteiro ou na conversa. A visão geral mostra onde o PR está: aprovado ou com alterações solicitadas, o veredito de cada revisor, as verificações de CI com um clique até os logs de qualquer verificação, e a conversa completa como uma linha do tempo legível. PRs abertos são checados a cada minuto; se a branch avançar, um clique atualiza e seus rascunhos sobrevivem.

Add to Review

O padrão (adicionar à revisão): junta os rascunhos localmente. Envie tudo de uma vez — Comment, Approve ou Request Changes — ou salve uma revisão pendente para concluir no github.com.

Comment Now

Publica um único comentário de revisão na hora (comentar agora), ancorado no bloco — ou restrito só às linhas que você selecionar no compositor.

Edit as Suggestion

O lápis abre o código Markdown do bloco num editor (editar como sugestão) — sua alteração é publicada como uma ```suggestion que o autor aplica com um clique.

leitura

Um leitor de verdade para o Markdown que já está no seu disco.

Suas anotações, seus READMEs, a pasta de docs do seu time — abra um arquivo ou um diretório inteiro e leia do jeito que ele foi feito para ser visto. Tudo re-renderiza no instante em que muda no disco, imagens e links relativos simplesmente resolvem, e se o GitHub renderiza, o PullMark renderiza:

Negrito, itálico, tachado, código inline, destaque, H2O, mc2, eiπ + 1 = 0, links com prévia ao passar o mouse, notas de rodapé[1], listas de tarefas — e mais tabelas, diagramas Mermaid, código com realce de sintaxe, alertas > [!NOTE], matemática KaTeX offline, [toc] e YAML front matter dobrado numa tabela de metadados organizada.

  • História na margem — uma régua de blame discreta: um avatar por sequência de blocos; passe o mouse para autor, data e commit; clique para o histórico completo das linhas.
  • Sempre atual — salve em qualquer editor e a página já re-renderizou.
  • Diff contra o histórico — um clique compara o arquivo de trabalho com qualquer commit ou branch recente, renderizado como um diff de PR, ao vivo enquanto o arquivo continua mudando; pullmark --diff faz isso do terminal — o caminho mais rápido para “o que o agente acabou de mudar no meu doc”.
  • Navegue sem se soterrar — vá de clique em clique por uma pasta ou um repositório e cada arquivo aparece como prévia: uma única entrada em itálico em Open Files que o próximo clique substitui. Clique duas vezes (ou simplesmente comece a editar) para mantê-lo.
  • Outline (estrutura) — um mapa dos seus títulos no estilo navegador, a um toque de distância.
  • Encontre qualquer coisa — ⌘F percorre as ocorrências na página; ⇧⌘F busca em todos os arquivos da barra lateral de uma vez.
  • Zoom que reflui — ⌘+ e ⌘− (ou uma pinça) escalam texto, imagens e a coluna de leitura juntos, lembrados entre as aberturas do app; a navegação cresce junto.
  • Clique para inspecionar — imagens, diagramas Mermaid e fórmulas de bloco abrem num overlay focado de pan e zoom, para diagramas complexos não ficarem presos à largura da coluna — e salve ou compartilhe exatamente o que você está inspecionando (diagramas como SVGs de verdade).
  • Leve para onde quiser — exporte como PDF ou como um único arquivo HTML autossuficiente; ⌘C cola texto rico no Docs e no Slack, ⌥⌘C devolve o Markdown.
  • Três temas de leitura — Editorial, GitHub e Terminal, com prévias ao vivo nos Settings (Ajustes) — ou traga seu próprio CSS. Claro & escuro reestilizam tudo, Mermaid incluído, e o comprimento de linha é seu: Standard, Wide ou Full Width.
  • Links do GitHub abrem no app — clique num link de github.com para um arquivo Markdown e o PullMark o renderiza, com uma barra de procedência repo @ branch sempre visível; ⌘-clique manda para o navegador.
  • Open Quickly (abrir rapidamente) — ⌘K pula para qualquer título, arquivo ou PR, com busca aproximada — ou cole a URL de um PR, a URL de um repositório ou um caminho de arquivo e ele abre direto.
  • Movido é movido — um parágrafo realocado ao pé da letra renderiza uma só vez, com um chip violeta discreto, não com ruído vermelho-mais-verde.
  • Continua de onde você parou — seus arquivos, PRs e posição de leitura são restaurados na abertura.

Esses são os destaques. A documentação cobre o resto — cada recurso, cada ajuste, cada ícone, o mapa completo do teclado e o comando pullmark.

Leitura por padrão. Edição no lugar.

Pressione ⌘E e a página vira o editor: o bloco sob o cursor revela seu Markdown cru ali mesmo — mesma tipografia, mesma posição, nada pula — e você já está digitando. Percorra os blocos com as setas, mescle com Backspace, divida com uma linha em branco; sair de um bloco o salva pelo mesmo caminho protegido e versionado de todo o resto. A leitura continua sendo o padrão; a fronteira entre os modos é o gesto de salvar.

O GitHub é um lugar onde seus docs moram. Leia-o como tal.

Clique num link de github.com para um arquivo Markdown e o PullMark o busca e renderiza dentro do app — o primeiro clique pergunta qual comportamento você prefere, e ⌘-clique sempre faz o outro. Uma barra de procedência acima da página diz exatamente que repositório e branch você está lendo, fixados no commit em que resolveram; links relativos continuam resolvendo contra o repositório, a árvore Markdown inteira está a um clique na barra lateral, e repositórios privados usam o login do GitHub que seus PRs já usam — nada do que é buscado toca o disco. Branches são um chip em cada repositório: troque no lugar, abra outra branch como uma entrada própria na barra lateral ou pule para uma worktree local. E se o repositório já estiver clonado no seu Mac naquela branch, o link abre seu arquivo local.

nativo

Um app de Mac que se comporta como um.

Quick Look

Pressione espaço sobre qualquer arquivo Markdown no Finder e veja-o renderizado no seu tema de leitura, antes mesmo de abrir qualquer app.

Uma CLI de verdade

pullmark README.md, pullmark ~/wt docs/plan.md — arquivos, pastas e worktrees abrem no app em execução, sempre na janela da frente. pullmark --help documenta tudo; a documentação também.

App padrão para .md

Um clique nos Settings (Ajustes) faz o clique duplo no Finder significar renderizado, em todo lugar — e se alguma atualização derrubar o vínculo, o PullMark percebe e o oferece de volta.

As credenciais que você já tem

Nenhum login separado. O PullMark usa gh auth token ou o credential helper do seu git — repositórios privados e de organizações simplesmente funcionam.

Nada fica no disco

O conteúdo de PR buscado vive em sessões efêmeras e caches de memória limitados — nada vindo do GitHub é gravado em armazenamento persistente.
