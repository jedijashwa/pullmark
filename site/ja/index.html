ドキュメントは、差分を取る 読むためにある。

PullMark は、ローカルの Markdown を読み手が目にするその姿でレンダリングします。そしてドキュメント中心の GitHub プルリクエストを、変わった単語だけをハイライトしたレンダリング差分として表示。 +/− だらけの文章の壁に目を凝らすことなく、コメントも、提案も、レビューの送信もできます。

あなたのエージェント

エージェントは計画を書く。
それを、同僚の文書のようにレビューする。

エージェントは大量の Markdown を生み出します。実装計画、仕様書、調査レポート——誰かが動き出す前に、 あなたの判断を必要とする長い文書たちです。ところが、その判断を伝える既存の手段は、どれもこの仕事に 向いていません。エディタで生ソースを読めば、読み手が見るはずの姿は隠れてしまう。チャットに断片を 貼り付ければ、フィードバックは元の場所から切り離される。PR のコメント欄ほしさに作業中のドラフトを コミットするのは、ただの儀式です——すべての文書がプルリクエストに収まるべきとは限りません。

マージンノートは、フィードバックを文書そのものの中に置きます。ドラフトを レンダリングされた姿で読み、気になった箇所をクリックして、そのブロックに固定された署名付きノートを 残す。ノートの実体はごく普通の HTML コメントで、レンダリングされたページには現れません。だから 「計画のノートに対応して」のひと言で受け渡しは完了。エージェントは、あなたが残したまさに その場所でノートを読みます。コミットも、貼り付けも、プルリクエストも不要。あとは修正が届くのを 眺めるだけ——Compare（比較）がエージェントの編集を単語単位でハイライトし、保存のたびにライブで 更新します。

エージェントに渡す指示文まで含めたループの全体は、エージェントの ページで順を追って説明しています。マージンノートはベータ版で、デフォルトで有効。仕組みの詳細は ドキュメントにあります。

なぜ

文章はコードではない。
コードの流儀でレビューするのは、やめよう。

覚えがあるはずです。README の差分に現れた 40 行の緑の壁と、そのどこかに埋もれた、実際に変わった たった一文。設計ドキュメント、意思決定の記録、運用手順書、エージェント定義——毎週レビューキューを 流れていくものは、どんどん文章になっています。そして文章のソース差分は、あなたが判断すべきその 当のものを覆い隠すのです。

PullMark は変更を、読み手が出会うその姿で見せます。レンダリングされたページの上で、 変わった単語だけがハイライトされる。表は表のまま、図は図のまま、一語の修正はハイライトされた 一語です。どのブロックにコメントしても、GitHub が期待する正確な行に着地します。承認も、変更の リクエストも、作者がワンクリックで適用できる提案も、そのままどうぞ。

「工房のとなりの、読書室。」
Note

PullMark は、あえてフルレビュークライアントにはしていません。表示するのは PR 内の Markdown ファイルだけ。変更のコード部分については、いつものレビューツールが引き続き 最適です。

レビュー

ドキュメントレビューのすべてを、レンダリングされたページから。

レイアウトはインラインと左右並列を切り替えられ、生の Source Diff（ソース差分）に降りることも、最終形の Result（結果）をプレビューすることもできます。 すべてツールバーから——ファイルからファイルへの移動も PR への戻りも、サイドバーに触れずに済みます。 YAML フロントマターは太字だらけの壁ではなく控えめなメタデータ表としてレンダリング されるので、設定の多いドキュメントもきれいに差分が取れます。新規ドキュメントは、全ブロックを緑に 染める代わりに「すべて新規」のひと言を添えて、一篇のドキュメントとして読めます。既存のレビュー スレッドは、話題にしているブロックの下に表示。ブロックにポインタを重ねてバブルをクリックすれば、 ブロック全体にも選んだ行だけにもコメントできます。仕上げは概要画面から Approve（承認）、Request Changes（変更のリクエスト）、 Comment（コメント）——行コメントの有無は問いません。ファイル単位のコメントや、 通常の会話コメントも残せます。概要画面が示すのは PR の現在地。承認済みか変更 リクエスト中か、各レビュアーの判定、ログまでクリックひとつでたどれる CI チェック、そして読みやすい タイムラインになった会話の全体です。開いている PR は毎分チェックされ、ブランチが動いたらワンクリックで 更新——下書きはそのまま残ります。

読む

ディスクの上にすでにある Markdown のための、ちゃんとしたリーダー。

自分のメモ、README、チームの docs フォルダ。ファイルひとつでもディレクトリ丸ごとでも 開いて、本来あるべき姿で読めます。ディスク上で変更された瞬間にすべてが再レンダリングされ、相対パスの 画像やリンクは当たり前のように解決されます。そして、GitHub がレンダリングするものなら、PullMark も レンダリングします。

太字、斜体、取り消し線、インラインコード、 ハイライト、H2O、mc2、 eiπ + 1 = 0、 ホバープレビュー付きのリンク、脚注[1]、 タスクリスト——さらに表、Mermaid 図、 シンタックスハイライト付きコード、> [!NOTE] アラート、オフラインの KaTeX 数式、 [toc]、そして整ったメタデータ表に折りたたまれる YAML フロントマター。

  • 余白に宿る履歴 — 控えめな blame ガター。連続ブロックのまとまりごとに アバターがひとつ。ホバーで作者・日付・コミット、クリックで行履歴の全体へ。
  • つねに最新 — どのエディタから保存しても、ページはもう再レンダリング されています。
  • 履歴との差分 — ワンクリックで、作業中のファイルを最近の任意のコミットや ブランチと比較。PR の差分と同じレンダリングで、ファイルが変わり続けてもライブで追従します。 pullmark --diff ならターミナルから——「エージェントはいま自分のドキュメントに 何をした？」への最速の答えです。
  • 埋もれないブラウズ — フォルダやリポジトリをシングルクリックでたどると、 各ファイルはプレビューとして開きます。Open Files に置かれる斜体の 1 行だけが使われ、 次のクリックで入れ替わります。ダブルクリック（または編集の開始）で確定です。
  • アウトラインサイドバー — 見出しを一望するナビゲータ風マップ。トグル ひとつで現れます。
  • 何でも検索 — ⌘F でページ内の一致を順にたどり、 ⇧⌘F でサイドバーの全ファイルを一括検索。
  • リフローするズーム — ⌘+ と ⌘−（またはピンチ）で テキスト・画像・本文カラムがまとめて拡大縮小。起動をまたいで記憶され、ナビゲーションも 一緒に育ちます。
  • クリックで拡大表示 — 画像・Mermaid 図・ブロック数式は、パンとズームの できる専用オーバーレイで開きます。複雑な図がカラム幅に閉じ込められることはありません。 見ているそのものを保存・共有でき、図は本物の SVG として書き出せます。
  • どこへでも持ち出せる — PDF や自己完結した単一の HTML として書き出し。 ⌘C は Docs や Slack にリッチテキストで貼り付き、⌥⌘C は Markdown を 返します。
  • 3 つの読書テーマ — Editorial、GitHub、Terminal。Settings（設定）でライブ プレビューでき、自作の CSS を置くこともできます。ライトとダークは Mermaid まで含めてすべてを 着替えさせ、行の長さも Standard・Wide・Full Width から選べます。
  • GitHub リンクはアプリ内で — Markdown ファイルへの github.com リンクをクリックすると PullMark がレンダリングし、リポジトリ @ ブランチの出所バーが つねに表示されます。⌘ クリックならブラウザへ。
  • Open Quickly — ⌘K であいまい一致から任意の見出し・ファイル・PR に ジャンプ。PR の URL、リポジトリの URL、ファイルパスを貼り付ければ、それを直接開きます。
  • 移動は移動として — そのまま場所を変えた段落は、赤と緑のノイズではなく、 控えめな紫のチップ付きで一度だけレンダリングされます。
  • 続きから再開 — ファイルも PR も読書位置も、起動時に復元されます。

ここまでがハイライトです。残りはドキュメントに—— すべての機能、すべての設定、すべてのアイコン、キーボードマップの全体、そして pullmark コマンド。

読むのが基本。編集は、その場で。

⌘E を押すと、ページがそのままエディタになります。カーソルの下のブロックが その場で生の Markdown を見せ——書体も位置もそのまま、何も跳ねません——すぐに入力を始められます。 矢印キーでブロックを移り、Backspace で結合、空行で分割。ブロックを離れると、他のすべてと同じ ガード付き・バージョン管理された経路で保存されます。基本はあくまで読むこと。モードの境界は、 保存という所作です。

GitHub はドキュメントの住まい。だから、読む場所として扱う。

Markdown ファイルへの github.com リンクをクリックすると、PullMark が アプリ内で取得してレンダリングします。最初のクリックでどちらの動作にするか尋ね、⌘ クリックは つねにもう一方を実行。ページ上部の出所バーが、いま読んでいるリポジトリとブランチを、解決された コミットに固定して正確に示します。相対リンクはリポジトリを基準に解決され続け、Markdown ツリーの全体は サイドバーからワンクリック。プライベートリポジトリには PR がすでに使っている GitHub サインインが そのまま使われ、取得した内容がディスクに触れることはありません。どのリポジトリにもブランチのチップが 付き、その場で切り替えるのも、別ブランチを独立したサイドバー項目として開くのも、ローカルの ワークツリーに飛び移るのも自在。しかも、そのブランチのリポジトリがすでに Mac 上にクローンされて いれば、リンクはローカルファイルの方を開きます。

ネイティブ

Mac アプリらしく振る舞う、Mac アプリ。

クイックルック

Finder で Markdown ファイルを選んでスペースキーを押せば、アプリを開くまでもなく、 読書テーマでレンダリングされた姿が見られます。

本物の CLI

pullmark README.md、pullmark ~/wt docs/plan.md——ファイルも フォルダもワークツリーも、起動中のアプリの、つねに最前面のウィンドウに開きます。 pullmark --help にもドキュメントにも詳細があります。

.md のデフォルトアプリに

Settings のワンクリックで、Finder のダブルクリックがどこでも「レンダリングして開く」の 意味になります。アップグレードで関連付けが外れても、PullMark が気づいて取り戻しを申し出ます。

いつもの認証情報で

独自のログインはありません。PullMark は gh auth token か git の credential helper を使うので、プライベートリポジトリも組織のリポジトリもそのまま動きます。

ディスクには何も残さない

取得した PR の内容は、一時的なセッションと上限付きのメモリキャッシュの中だけに存在します。 GitHub から来たものが永続ストレージに書き込まれることはありません。
