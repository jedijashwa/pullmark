Solución de problemas

Las pocas cosas que se tuercen, qué significan los mensajes de PullMark y el diseño que hay detrás de los fallos más callados — casi todos los «errores» de esta página son la app negándose deliberadamente a perder tu trabajo.

Acceso a GitHub: cómo se conecta PullMark, y cómo arreglarlo

PullMark toma prestadas las credenciales de GitHub que ya tienen tus propias herramientas — no tiene inicio de sesión propio y jamás guarda un secreto. Ajustes → General → GitHub muestra si está conectado, como quién y por qué fuente; Configurar… guía a una máquina nueva por la conexión, y Volver a comprobar recoge el arreglo al instante — tras gh auth login, sin relanzar nada.

¿Lees esto en el Mac donde PullMark (0.36+) está instalado? Abre ahora la fila de conexión.

Las fuentes de credenciales, en el orden en que PullMark las prueba:

  1. El token de la CLI de GitHub: gh auth token tiene que imprimir uno. Si no, brew install gh && gh auth login — el camino recomendado: su token lleva ámbitos que se sabe que funcionan, resuelve el SSO en el flujo del navegador y se refresca.
  2. Si no, git credential fill — lo que use el propio git para github.com (el llavero de macOS, Git Credential Manager, un token que dejó guardado un push HTTPS antiguo).

La letra pequeña de los tokens, para los que funcionan a medias: los tokens clásicos necesitan el ámbito repo (y read:org para los nombres de equipo de una organización); los tokens detallados (fine-grained) están atados a un único propietario de recursos — funcionan los repos públicos y los privados de ese propietario, y todo lo demás se deniega; las organizaciones protegidas con SSO necesitan el token autorizado para cada una; y los tokens creados a mano caducan — la fila de Ajustes es donde se diagnostica el «ayer funcionaba».

GitHub: «puede que no exista… o que sea un repositorio privado»

«No se pudo abrir … Puede que no exista en esa ref, o que sea un repositorio privado al que tus credenciales de GitHub no tienen acceso.» La API de GitHub informa igual del «privado sin acceso» y del «no existe», así que PullMark no puede decirte cuál de los dos es. Si el repo debería funcionar, casi siempre es la autenticación — mira Acceso a GitHub más arriba, o abre Ajustes → General → GitHub y pulsa Configurar….

Gatekeeper no abre la app

Las versiones van firmadas con un Developer ID y notarizadas por Apple, así que una descarga normal no muestra ninguna advertencia. Si la compilaste desde el código fuente (make app), la app va firmada ad hoc: clic derecho → Abrir → Abrir, o autorízala en Ajustes del Sistema → Privacidad y seguridad.

Las vistas previas de Quick Look dejaron de renderizarse

Una actualización de Homebrew reemplaza el paquete de la app, y eso puede tirar en silencio el registro de la extensión de Quick Look. PullMark la vuelve a registrar en cada arranque — así que basta con abrir la app una vez. Si las vistas previas siguen mostrando texto crudo, comprueba que Ajustes → General → «Vistas previas de Quick Look» esté en Renderizado.

«PullMark ya no es tu app por defecto para Markdown»

La misma causa: una actualización reemplazó el paquete y macOS soltó el vínculo con .md. El Volver a hacerlo la app por defecto del aviso lo recupera; Ajustes → General también.

«… cambió mientras editabas este bloque — no se guardó nada»

El archivo cambió en disco (otro editor, un agente, una operación de git) entre que abriste el editor del bloque y guardaste. PullMark se niega a injertar texto en líneas que se han movido — no se pierde nada salvo esa edición, y volver a abrir el bloque muestra el texto actual. La misma salvaguarda protege los commits: comparar contra una ref donde el archivo no existe se cuenta con todas las letras, en vez de mostrar un diff vacío.

Filas atenuadas: carpetas y recientes que «no están»

Una Ubicación con una insignia de interrogación, o un reciente en gris, significa que la ruta no se resuelve ahora mismo — un volumen desmontado, una rama de git cambiada, un worktree borrado. Las filas se atenúan en vez de desaparecer a propósito: reviven solas cuando la ruta vuelve. Clicar un reciente muerto ofrece Quitar de recientes o Conservar.

Pull requests: avisos y comentarios pendientes

  • «Este pull request se actualizó en GitHub.» — la rama se movió desde que lo cargaste. Refrescar es un clic y tus borradores de comentario sobreviven; PullMark nunca recarga por su cuenta debajo de una revisión en curso.
  • «No se pudieron cargar los comentarios de revisión…» — sin ese aviso, el diff se haría pasar por un PR sin comentar; Reintentar vuelve a pedirlos.
  • «No se pudieron subir N comentarios pendientes a GitHub — se conservan en local para reintentarlo.» — los comentarios escritos sin conexión (o durante un tropiezo de la API) se encolan en disco por cabeza de PR y suben cuando pueden. No se descarta nada.
  • «Se hizo commit de …, pero el push falló» — el commit está a salvo en tu historial local; lo único que hay que reintentar es el push.

Actualizaciones

El Actualizar ahora del aviso ejecuta el upgrade de brew (o una instalación verificada en el sitio, para las instalaciones por DMG) y relanza la app. Si falla, el aviso muestra el comando exacto brew upgrade --cask pullmark con un botón Copiar — ejecutarlo en una terminal hace lo mismo. Las compilaciones de desarrollo no buscan actualizaciones.

El comando pullmark

  • «no such file or folder» — el comando verifica todas las rutas antes de abrir nada; una errata aborta la apertura entera (código de salida 1), para que los scripts fallen en voz alta.
  • Command not found — ver instalar el comando.
  • «Couldn't install the command» — el instalador de Ajustes necesita autorización para escribir en /usr/local/bin; si descartaste el diálogo, cancela y vuelve a lanzarlo.
