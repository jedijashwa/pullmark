Funciones

El recorrido, agrupado por lo que estás haciendo: leer, revisar, navegar GitHub, editar y sacar documentos. PullMark deliberadamente no es un cliente de revisión completo — muestra el Markdown de un cambio; tus herramientas de siempre siguen siendo las adecuadas para el código.

Lectura

  • Renderizado fiel a GitHub — tablas, listas de tareas, notas al pie, alertas, <details> plegables, resaltado de sintaxis, diagramas Mermaid y fórmulas KaTeX ($…$ / $$…$$), todo sin conexión. Un párrafo con solo [toc] se convierte en una tabla de contenidos con enlaces; ==highlight==, ~sub~ y ^sup^ también se renderizan.
  • Clic para inspeccionar — las imágenes, los diagramas y las fórmulas en bloque se abren en una vista superpuesta con desplazamiento y zoom; Save As… (guardar como) y Share (compartir) exportan exactamente lo que estás inspeccionando (los diagramas, como SVG de verdad).
  • Archivos vivos — los documentos se vuelven a renderizar al guardarse desde cualquier editor; las imágenes y enlaces relativos se resuelven, y hacer clic en un enlace a otro archivo Markdown lo abre en el sitio (como vista previa cuando vive en una Location abierta).
  • Navegación — la barra lateral de esquema (⌥⌘O), buscar en la página con ⌘F, buscar con ⇧⌘F en todos los archivos de la barra lateral a la vez, y Open Quickly (abrir rápidamente, ⌘K) para encabezados, archivos, PR y recientes — o pega directamente una ruta o una URL de GitHub.
  • Blame a altura de lectura — un margen discreto de autoría: un avatar por grupo de bloques, pasa el cursor para ver el commit, haz clic para el historial de líneas. La API de blame de GitHub cuando el archivo vive en GitHub, git blame a secas en el resto de casos.
  • Comodidad de lectura — temas, ancho del contenido, números de línea (Ajustes), zoom al estilo del navegador, claro/oscuro, pantalla completa y la posición de lectura recordada por documento.

Revisar pull requests

  • Diffs renderizados — bloques añadidos, eliminados y modificados resaltados en la página renderizada, diffs palabra por palabra cuando la edición es lo bastante pequeña para tener sentido, en línea o lado a lado (⌥⌘L), más el Source Diff crudo (⌘2) y el Result final (⌘3). Los párrafos movidos reciben un discreto chip de «movido» en lugar de ruido rojo y verde.
  • Hilos de revisión en el sitio — los comentarios existentes aparecen bajo los bloques que discuten; pasa el cursor por un bloque para Comment Now (comentar ahora), Add to Review (añadir a la revisión) o Insert Suggestion (insertar sugerencia) — y el lápiz edita el bloque como sugerencia. Las revisiones se envían con un veredicto, o se guardan en GitHub como revisión pendiente.
  • En qué punto está el PR — la cabecera del resumen muestra la decisión de revisión (aprobado, cambios solicitados, revisión requerida), el veredicto de cada revisor como avatares con insignia junto a los revisores pendientes, y una cápsula de checks de CI que se despliega en la lista completa — duraciones, etiquetas de obligatorio y un enlace a los logs de cada check. Todo se refresca en silencio cada minuto.
  • La conversación, legible — una sola cronología en el resumen: comentarios y veredictos de revisión en orden, con los comentarios en línea de cada revisión anidados bajo su resumen y el archivo que discuten nombrado en la tarjeta. Reacciones, editar y borrar tus propios comentarios, y el cuadro de comentario al pie de la cronología. Activo para todos (Settings ▸ General ▸ Reviewing esconde los hilos).
  • Siempre al día — los PR abiertos se comprueban cada minuto; un aviso ofrece refrescar cuando la rama avanza, y tus borradores de comentario sobreviven. Los comentarios escritos sin conexión se encolan y suben cuando pueden.
  • Solicitudes de revisión — los PR que esperan tu revisión, en la barra lateral con contadores de no leídos. Las imágenes del PR y los enlaces relativos al repo se resuelven en el commit del PR.

GitHub, sin el navegador

  • Los enlaces Markdown se abren en la app — haz clic en un enlace github.com/…/blob/… y PullMark lo renderiza (el primer clic pregunta; ⌘-clic invierte tu opción por defecto). Una barra de procedencia fija owner/repo @ ref · ruta con un camino de vuelta a GitHub.
  • Navega repos enteros — carga el árbol Markdown de un repo en Locations, cambia de rama, compara contra otras ramas, consulta el blame — los repos privados usan las credenciales que los PR ya usan, y nada de lo descargado toca el disco.
  • Ramas y worktrees — los checkouts locales llevan un chip de rama; su menú abre worktrees como Locations propias y lee otras ramas en remoto. Lo local siempre gana a lo remoto cuando un worktree ya tiene la rama.

Editar y hacer commit

  • Editar en el sitio — el lápiz de un bloque (o ⌘E para el documento entero) convierte los bloques en editores dentro de la página renderizada; ⌘↩ guarda, Esc cancela. Los guardados están protegidos contra cambios del archivo por debajo, y versionados para Revert Last Edit (revertir la última edición).
  • Commit desde la app — ⌃⌘K abre la hoja de commit del repo del archivo: elige archivos, escribe el mensaje, haz push si quieres, con una salvaguarda antes de hacer commit directo a main.

Comparar con el historial

  • Cualquier archivo, cualquier revisión — el botón Compare de la barra de herramientas (el reloj con chevron) compara el archivo de trabajo contra cualquiera de sus últimos 25 commits, o contra cualquier rama local o remota — renderizado, con las palabras cambiadas resaltadas, exactamente como un pull request. Un punto discreto en el botón significa que el archivo tiene cambios sin commit.
  • «¿Qué acabo de cambiar?» — un elemento de menú (View → Compare with Last Commit) o un comando de shell (pullmark --diff file.md, ver la CLI). El diff sigue el ritmo del archivo mientras cambia — mira aterrizar las ediciones de un agente, resaltadas, a medida que guarda.

Sacar los documentos

  • Exportar — PDF (una sola página continua) o HTML totalmente autocontenido; Share envía el documento a cualquier sitio al que macOS llegue.
  • Copiar en dos sabores — ⌘C es texto con formato para Docs/Slack; ⌥⌘C es el Markdown subyacente.
  • Imprimir — ⌘P, al 100 % sin importar el zoom.
  • Quick Look — espacio en el Finder previsualiza el Markdown con el renderizado del propio PullMark.

Una barra de herramientas que es tuya

Haz clic derecho en la barra de herramientas — o View → Customize Toolbar… — para abrir la paleta de personalización nativa: arrastra fuera lo que nunca usas, reordena el resto, añade Flexible Space (espacio flexible). Cada tipo de vista conserva su propia disposición, recordada entre sesiones: un archivo local, un doc de GitHub, un archivo de pull request y el resumen del PR son barras distintas, y cada una se personaliza estando en ella — igual que la ventana de redacción de Mail conserva su propia barra.

Más allá del juego por defecto, la paleta guarda elementos que empiezan ocultos: un conmutador de Source (código fuente) crudo, Zoom In / Actual Size / Zoom Out, el selector de Content Width (ancho del contenido), Add Margin Note (añadir nota al margen — mientras la función esté activada) y, para docs de GitHub, Share — la página github.com del documento, nunca un enlace crudo — y Reload, que vuelve a resolver la rama a su punta actual y permanece desactivado, con el motivo, para documentos abiertos en un commit concreto. De fábrica nada cambia; la paleta guarda el resto. La barra de herramientas lista los elementos de cada vista.

Todo lo demás

  • Ventanas y pestañas — ⌘N abre una ventana independiente; fusiónalas en pestañas nativas. Las aperturas externas caen en la ventana frontal.
  • El comando pullmark — archivos, carpetas y worktrees desde cualquier terminal. Ver Línea de comandos.
  • Control de la app por defecto — haz de PullMark el manejador de .md con un clic, y se dará cuenta si una actualización rompe el vínculo.
  • Actualizaciones integradas — versiones firmadas y notarizadas, con actualización en un clic y una hoja de novedades (What's New).
  • Postura de privacidad — el contenido de GitHub se descarga por la API y se mantiene en memoria, y los documentos jamás se copian a ningún sitio. La página de privacidad tiene la historia completa.
