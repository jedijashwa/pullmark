La barra de herramientas

Una barra de herramientas por tipo de vista, todas totalmente personalizables: haz clic derecho sobre ella (o View → Customize Toolbar…) y arrastra elementos fuera, reordénalos, añade lo que empieza oculto. Cada vista recuerda su propia disposición entre sesiones.

Cómo funciona la personalización

PullMark no tiene una sola barra de herramientas — tiene una por tipo de vista, igual que la ventana de redacción de Mail lleva una barra distinta de la de su ventana principal. Personalizas la barra que estás mirando: abre un archivo de pull request para personalizar la barra de archivos de PR, un documento local para la de archivos locales. La paleta solo ofrece los elementos que existen allí donde la abriste.

Todo lo de la paleta es terreno libre — quítalo, reordénalo, suelta Flexible Space (espacio flexible) para separar grupos. Los elementos marcados oculto más abajo empiezan en la paleta y no en la barra. El único lugar al que los elementos no van es la franja propia de la barra lateral, junto a su conmutador: esa sección pertenece al sistema, y lo que sueltes ahí se acomoda al principio de la sección principal. Restaura cualquier barra arrastrando de vuelta el juego por defecto desde el fondo de la paleta.

Open File or Foldervisible Abre Markdown local o una carpeta como Location.
Open Pull Requestvisible Abre un pull request de GitHub por URL.
Appearancevisible Light · Dark · System, para toda la app.

Documentos de GitHub

Documentos leídos directamente de un repo — abiertos desde enlaces, ⌘K o una Location de repo navegado.

ElementoPor defectoQué hace
ComparevisibleEl mismo documento en otra rama, como diff renderizado.
BlamevisibleBlame por bloque desde la API de GitHub.
OutlinevisibleLa barra lateral de encabezados.
Shareoculto La página github.com del documento — el enlace que una persona quiere de verdad, nunca una URL cruda.
Reloadoculto Vuelve a resolver la rama a su punta actual y descarga de nuevo. Desactivado — con el motivo — para documentos abiertos en un commit concreto, que no puede cambiar.
SourceocultoEl Markdown crudo.

El resumen del PR, y docs de repo navegados desde un PR

El resumen se mantiene mínimo: Share (la página de GitHub del pull request) más los elementos comunes a todas las vistas. Un documento de repo navegado desde el contenido de un PR lleva Blame y Outline, con los elementos de zoom y Content Width en su paleta.
