Die Toolbar

Eine Toolbar pro Art von Ansicht, jede voll anpassbar: Rechtsklick darauf (oder View → Customize Toolbar…), zieh Elemente raus, ordne sie neu, hol dazu, was versteckt startet. Jede Ansicht merkt sich ihre eigene Anordnung über Starts hinweg.

Wie das Anpassen funktioniert

PullMark hat nicht eine Toolbar — es hat eine pro Art von Ansicht, so wie das Verfassen-Fenster von Mail eine andere Toolbar behält als sein Hauptfenster. Du passt die Toolbar an, die du gerade vor dir hast: Öffne eine Pull-Request-Datei, um die PR-Datei-Toolbar anzupassen, ein lokales Dokument für die Toolbar lokaler Dateien. Die Palette bietet immer nur die Elemente an, die es dort gibt, wo du sie geöffnet hast.

Alles in der Palette ist verhandelbar — raus damit, umsortieren, Flexible Space dazwischen, um Gruppen auseinanderzuschieben. Elemente, die unten als versteckt markiert sind, starten in der Palette statt in der Leiste. Der einzige Ort, an den nichts wandert, ist der eigene Streifen der Seitenleiste neben dem Seitenleisten-Schalter: Dieser Bereich gehört dem System, und was du dort fallen lässt, landet stattdessen vorn im Hauptbereich. Jede Toolbar stellst du wieder her, indem du den Standardsatz vom unteren Rand der Palette zurückziehst.

In jeder Ansicht

ElementStandardWas es tut
Reviewsichtbar Das mitwachsende Review-Element, nur in PR-Ansichten — Zahl der ausstehenden Kommentare, Urteil, Absenden. Übersteht ein schmales Fenster am längsten: Der Review-Status bleibt sichtbar, wenn andere Elemente ins Overflow-Menü rutschen.
Open File or Foldersichtbar Lokales Markdown oder einen Ordner als Ort öffnen.
Open Pull Requestsichtbar Einen GitHub-Pull-Request per URL öffnen.
Appearancesichtbar Light · Dark · System, für die ganze App.

Lokale Dateien

ElementStandardWas es tut
SharesichtbarDas übliche Share-Sheet für die Datei.
EditsichtbarEdit Mode — klick einen beliebigen Block, um ihn an Ort und Stelle zu bearbeiten.
Comparesichtbar Mit einem Commit oder Branch vergleichen (braucht ein Git-Repository). Ein kleiner Punkt heißt: Die Datei hat uncommittete Änderungen.
Blamesichtbar Wer jeden Block zuletzt geändert hat; außerhalb eines Repositorys deaktiviert.
OutlinesichtbarDie Gliederungs-Seitenleiste.
ReloadsichtbarDie Datei neu von der Platte lesen.
SourceverstecktDas rohe Markdown hinter der gerenderten Seite.
Zoom In · Actual Size · Zoom Outversteckt Einzelne Elemente — nimm nur das Paar, das du wirklich benutzt.
Content WidthverstecktStandard · Wide · Full Width.
Add Margin Noteversteckt Nur in der Palette, solange Randnotizen eingeschaltet sind.

GitHub-Dokumente

Dokumente, die direkt aus einem Repo gelesen werden — geöffnet über Links, ⌘K oder ein durchstöbertes Repo unter „Orte".

ElementStandardWas es tut
ComparesichtbarDasselbe Dokument auf einem anderen Branch, als gerendertes Diff.
BlamesichtbarBlame pro Block, aus der GitHub-API.
OutlinesichtbarDie Gliederungs-Seitenleiste.
Shareversteckt Die github.com-Seite des Dokuments — der Link, den ein Mensch wirklich will, nie eine rohe URL.
Reloadversteckt Löst den Branch neu auf seine aktuelle Spitze auf und lädt neu. Deaktiviert — mit Begründung — für Dokumente, die an einem bestimmten Commit geöffnet wurden und sich gar nicht ändern können.
SourceverstecktDas rohe Markdown.
Zoom-Elemente · Content WidthverstecktWie bei lokalen Dateien.

Pull-Request-Dateien

ElementStandardWas es tut
Navigationsichtbar Zurück zur Übersicht, vorherige/nächste Markdown-Datei und das n-von-m-Sprungmenü — eine Gruppe, eine ziehbare Einheit.
View-Pickersichtbar Rendered Diff · Source Diff · Result, zentriert.
OutlinesichtbarDie Gliederungs-Seitenleiste.
Layoutsichtbar Inline oder nebeneinander — aktiv in der Rendered-Diff-Ansicht (neue Dateien rendern immer inline).
Blamesichtbar Aktiv in der Result-Ansicht, wo es ein fertiges Dokument zum Annotieren gibt.
Comment on Filesichtbar Ein Kommentar zur Datei als Ganzes, nicht zu einer bestimmten Zeile.
Zoom-Elemente · Content WidthverstecktWie bei lokalen Dateien.

Die PR-Übersicht — und Repo-Docs, die du aus einem PR heraus öffnest

Die Übersicht hält es knapp: Share (die GitHub-Seite des Pull Requests) plus die Elemente, die es in jeder Ansicht gibt. Ein Repo-Dokument, das du aus PR-Inhalten heraus durchstöberst, trägt Blame und Outline, mit den Zoom-Elementen und Content Width in seiner Palette.
