Die Seitenleiste

Vier Bereiche, geordnet danach, was Dinge bedeuten, nicht woher sie kommen: was du offen hast (Geöffnete Dateien), die Ordner und Repos, die du durchstöberst (Orte), die Pull Requests, die du reviewst — und wo du gewesen bist (Zuletzt benutzt).

Geöffnete Dateien

Das Arbeitsset: jedes Dokument, das du ausdrücklich geöffnet hast — aus dem Finder, per Drag & Drop, mit ⌘O, über die Kommandozeile oder indem du eine Datei aus einem Ort behalten hast. Flach, per Ziehen umsortierbar, jede Zeile mit dem Hover-✕ entfernbar (oder ⌫ auf der ausgewählten Zeile). Rechtsklick auf die Bereichsüberschrift für Close All.

Vorschauen

Ein Einzelklick auf eine Datei in einem Ort rendert sie sofort — und sie erscheint in „Geöffnete Dateien" als Vorschau: ein kursiver Eintrag, immer zuletzt im Bereich. Klick eine andere Datei und der Vorschau-Eintrag wird ersetzt — Stöbern durch einen großen Baum stapelt also nie Zeilen auf. Es ist dieselbe Idee wie die Vorschau-Tabs in VS Code oder Xcodes temporärer Editor, mit derselben Kursivschrift.

Eine Vorschau wird zu einem normalen, festen Eintrag, sobald du ihr mehr Verbindlichkeit zeigst als bloßes Lesen:

  • Doppelklick auf die Datei im Baum — oder auf den kursiven Eintrag selbst
  • Anfangen zu bearbeiten — der Edit Mode oder das Speichern einer Blockänderung pinnt sie fest
  • Keep Open im Rechtsklick-Menü

Lese-Interaktionen — Blame, Zeilenhistorie, ein Bild oder Diagramm inspizieren — befördern eine Vorschau absichtlich nie. Wenn du lieber jeden Klick Dateien voll öffnen lässt, stell Clicking files in Locations in den Einstellungen um.

Remote-Repos previewen genauso, am selben Ort. Beim Stöbern durch den Baum eines GitHub-Repos, oder beim Folgen von Links in einem Remote-Dokument, landet derselbe eine kursive Eintrag in „Geöffnete Dateien" — mit Buch-Icon und einer owner/repo @ ref-Zweitzeile, weil die Datei nicht auf deinem Mac liegt. Es gibt immer nur eine Vorschau pro Fenster, lokal oder remote: Etwas anderes zu previewen ersetzt, was du davor angesehen hast. Ein Remote-Doc zu behalten (Doppelklick oder Keep Open) heftet es bei seinem Repo ab — es wandert in die feste Liste des Repos unter „Orte". ⌘K öffnet direkt fest, denn eine URL einzufügen ist ausdrückliche Absicht.

Jede Zeile unter „Geöffnete Dateien", die in einem offenen Ort liegt, bekommt Reveal in Location ins Rechtsklick-Menü — der Sprung zurück von „was ich lese" zu „wo es wohnt".

Orte

Durchstöberbare Wurzeln, wo immer sie liegen. Zwei Arten teilen sich den Bereich, unterschieden per Icon:

ZeileBedeutung
📁 Ordner-IconEin lokaler Ordner — seine Markdown-Dateien als Baum (oder flache Liste; Rechtsklick → View as List). Wird auf Änderungen überwacht.
📕 Buch-IconEin GitHub-Repository, zum Stöbern geöffnet — über die API geladen, nichts wird auf die Platte geschrieben.

Ein lokaler Ordner, der ein Git-Checkout ist, bekommt einen Branch-Chip (Branch-Glyphe + Name); liegt sein Remote auf GitHub, kommt eine kleine Geschlossenes-Buch-Marke dazu — Hover zeigt, welches Repo. Ein Klick auf den Branch-Chip öffnet das Branches-und-Worktrees-Menü:

  • Worktrees — jeder Worktree des Repos, mit Häkchen auf dem, der diese Zeile ist; wähl einen anderen, um ihn als eigenen Ort zu öffnen. Worktrees werden von PullMark nie ausgecheckt oder gewechselt — es öffnet den Ordner, der schon da ist.
  • View Branch from GitHub — lies die Dateien eines anderen Branches remote, ohne deinen Checkout anzufassen. Ein Branch, der schon einen lokalen Worktree hat, springt stattdessen zum Worktree — lokal schlägt remote.
  • Open on GitHub — das Repo (auf diesem Branch) in deinem Browser.

Auf einem Remote-Repo (Buch-Icon) listet derselbe Chip Branches: Switch To pinnt die Session auf einen anderen Branch um, und mit gehaltenem ⌥ gibt es Open Branch Separately fürs Lesen nebeneinander. Browse Repo Files… lädt den ganzen Markdown-Baum des Repos. Die behaltenen Docs des Repos sitzen über dem Baum, damit sie in einem großen Repo nie untergehen; ein behaltenes Doc, das im Baum sichtbar ist, wird einfach dort dargestellt. (Ein Doc, das du nur previewst, erscheint unter Geöffnete Dateien, nicht hier.)

Ein Ordner, dessen Pfad nicht mehr auflöst (ein ausgeworfenes Volume, ein gelöschter Worktree), wird mit Fragezeichen-Badge gedimmt, statt zu verschwinden — er erwacht von selbst wieder, wenn der Pfad zurückkommt.

Pull Requests

Jeder geöffnete PR ist eine Gruppe: die Übersichtszeile (Status-Icon + Zahl geänderter Markdown-Dateien), dann seine geänderten Markdown-Dateien — eine Sprechblase mit Zahl markiert Dateien mit unaufgelösten Review-Threads. Unter deinen geöffneten PRs sammelt Review Requests (Review-Anfragen) PRs, die auf dein Review warten, mit einer Ungelesen-Zahl, die auch eingeklappt sichtbar bleibt (in den Einstellungen ausblendbar — und filterbar auf PRs, die Markdown anfassen).

Status-Icons auf PR-Zeilen:

StatusIcon
Draft (Entwurf)Pull-Request-Pfeile, grau
OffenPull-Request-Pfeile, grün
GemergedMerge-Pfeile, violett
Geschlossen✕ im Kreis, rot
Nicht verfügbarPapierkorb, grau — der PR (oder dein Zugriff) ist weg

Datei-Marker innerhalb eines PRs: +-Kreis (grün) für hinzugefügt, −-Kreis (rot) für entfernt, →-Kreis für umbenannt, Stift-Kreis für geändert.

Zuletzt benutzt

Kürzlich geöffnete Dateien, Ordner und Pull Requests, die oben nicht schon sichtbar sind. PR-Einträge tragen ihr Live-Status-Icon; ein Eintrag, dessen Datei verschwunden ist, wird gedimmt (Uhr-Badge), statt zu verschwinden, und erwacht wieder, wenn der Pfad zurückkommt — gebaut für Branch-Wechsel und ausgeworfene Volumes. Rechtsklick auf die Überschrift für Clear Recents.

Dinge entfernen

Fahr über eine beliebige Zeile der obersten Ebene für das ✕ — es entfernt die Zeile aus der Seitenleiste, nie etwas von der Platte oder von GitHub. ⌫ auf einer ausgewählten Zeile tut dasselbe. Dateien im Baum eines Ortes haben kein ✕: Sie sind sein Inhalt, keine Seitenleisten-Einträge.

Die Branch-Glyphe erscheint nur an echten Git-Refs (als Chip, nie als Ordner-Icon) — ein Ordner ist ein Ordner, ein Repo ist ein Buch, ein Branch ist ein Branch.
