Einstellungen

Alles hinter ⌘, — vier Tabs: General fürs Verhalten, Appearance dafür, wie PullMark aussieht, Keyboard für die Tastenbelegung und Experimental für Features, die sich noch setzen. Das Fenster geht in dem Tab wieder auf, den du zuletzt offen hattest.

General

Liest du das dort, wo PullMark (ab 0.28.1) installiert ist? Den General-Tab öffnen.

GitHub

EinstellungWas sie tut
Connection Ob PullMark mit GitHub sprechen kann, als wer, und über welche Quelle für Zugangsdaten („Connected as you · GitHub CLI"). Check Again liest die Zugangsdaten neu — nach gh auth login verbindet es ohne Neustart — und Set Up… öffnet eine Anleitung, die erkennt, was diesem Mac fehlt. Die ganze Geschichte steht unter GitHub-Zugriff.

Updates

EinstellungWas sie tut
Show What's New after an update An (der Standard) zeigt die Release Notes, sobald ein Update gelandet ist; aus tauscht das gegen ein leises Banner „Updated to PullMark X", die Notes einen Klick entfernt — ein Update meldet sich immer irgendwie.
Updates Check for Updates… auf Zuruf; PullMark prüft außerdem beim Start und in Abständen. Ist ein Update schon bekannt, bietet die Zeile gleich dort What's New, Update Now und einen Knopf zum erneuten Prüfen. What's New zeigt die Notes jedes Releases zwischen deiner Version und der neuen, und Help → Release Notes hat jederzeit die ganze Historie.

System

EinstellungWas sie tut
Default Markdown app Zeigt, welche App gerade .md-Dateien öffnet; Make PullMark the Default holt sich die Zuordnung mit einem Klick. Verwirft macOS sie bei einem späteren Upgrade, merkt PullMark das und bietet an, sie zurückzuholen.
Command line Installiert den pullmark-Befehl nach /usr/local/bin, für DMG-Installationen (wer Homebrew nutzt, hat ihn schon). Zeigt ein Häkchen, wenn schon ein pullmark in deinem PATH liegt.
Quick Look previews Rendered (der Standard) oder Raw Source — was die Leertaste im Finder für Markdown-Dateien zeigt.

Appearance

Liest du das dort, wo PullMark (ab 0.28.1) installiert ist? Den Appearance-Tab öffnen.

Der Schalter Light · Dark · System sitzt ganz oben — die ganze App folgt, Fensterrahmen wie gerenderte Seiten (jedes Theme bringt seinen eigenen hellen und dunklen Look mit). Darunter die visuellen Optionen:

Jede Wahl hier ist eine Karte mit einer Live-Vorschau, gerendert durch dieselbe Pipeline wie alles andere — was du siehst, bekommen deine Dokumente.

Keyboard

Liest du das dort, wo PullMark (ab 0.28.1) installiert ist? Den Keyboard-Tab öffnen.

Das Kürzel jeder Menüaktion lässt sich neu belegen — die volle Belegung, und wie Aufnehmen, Konflikte und Restore Defaults funktionieren, steht unter Tastaturkürzel.

Experimental

Liest du das dort, wo PullMark (ab 0.28.1) installiert ist? Den Experimental-Tab öffnen.

Features, die ausgeliefert werden, bevor ihr Design fertig ist, jedes markiert als beta oder alpha — der Stufen-Vertrag erklärt, was jede Stufe verspricht. Alpha-Features bleiben versteckt, bis du Show alpha features einschaltest (ein Dialog erklärt vorher die Alpha-Bedingungen), und jedes Feature hat seinen eigenen Schalter. Randnotizen wohnen hier — seit 0.35 in Beta und standardmäßig an, mit eigenem Schalter, Autor-Einstellung und einem Copy-Knopf für den Schnipsel mit den Agenten-Anweisungen; beim ersten Einsatz stellt sich das Feature vor und bietet gleich an, sich wieder abzuschalten.

Wo was gespeichert wird

Alle Einstellungen leben in der Defaults-Domain app.pullmark.PullMark. Sessions, Lesepositionen und Entwürfe sind reine Metadaten — PullMark kopiert deine Dokumente nie irgendwohin, und was von GitHub kommt, bleibt im Speicher.
