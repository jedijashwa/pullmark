文档，是拿来比对 阅读的。

PullMark 把你本地的 Markdown 渲染成读者将会看到的样子——并把以文档为主的 GitHub 拉取请求显示为渲染后的差异，只高亮真正改动的那几个词。评论、提建议、 提交审查，全程不必再对着一堵 +/− 的文字墙眯眼睛。

你的智能体

你的智能体在写计划。
把它当同事的稿子来审。

智能体会产出大量 Markdown：实现计划、规格说明、调研报告——都是些在任何人动手之前、 需要你先下判断的长文档。可眼下能用来传达这份判断的几种方式，没有一种称职。在编辑器里读 原始源码，读者会看到的样子就被藏了起来；把片段贴进聊天窗口，反馈便与它所指的位置断了联系； 而为了拿到 PR 的评论框，把一份还在改的草稿提交上去，纯属仪式——并不是每份文档都该走一遍 拉取请求。

页边批注（Margin Notes）把反馈放进文档本身。渲染着读这份草稿，在不对劲 的地方点一下，留下一条署名的批注，锚在那个区块上。批注是不会出现在渲染页面上的普通 HTML 注释——所以一句“把计划里的批注都处理掉”就是全部交接：智能体会在你留下批注的确切 位置逐条读到它们。不用提交，不用粘贴，不用开拉取请求。然后看着修订落地——Compare（比较） 把智能体的改动逐词高亮，随它保存实时更新。

整个闭环——连同要交给智能体的那段指令——都在智能体 页面上走了一遍。页边批注目前是 beta，且默认开启；文档讲清了它的机制。

为什么

文字不是代码。
别再照着代码的样子审它。

那一幕你熟悉：README 的差异里立着四十行绿墙，而真正改动的那一句，就埋在墙里的某处。 设计文档、决策记录、运行手册、智能体定义——每周流过你审查队列的东西，越来越多是文字； 而文字的源码差异，恰恰藏起了你来这一趟要判断的东西。

PullMark 把改动按读者将会遇见它的样子摆给你看：渲染出来，只高亮改动的词。 表格还是表格，图表还是图表，改了一个词就只有一个词被点亮。对任意区块评论，评论都会落在 GitHub 期待的那几行上——批准、请求更改，或者留下作者一键就能应用的建议。

“工作间隔壁的那间阅览室。”
注意

PullMark 有意不做完整的审查客户端。它只显示 PR 里的 Markdown 文件—— 改动中的代码部分，你惯用的审查工具依然是对的地方。

审查

整场文档审查，都在渲染好的页面上完成。

在行内与并排两种版式之间切换，落到原始的 Source Diff（源码差异），或者预览最终的 Result（结果）——全都在工具栏上； 工具栏还带你从一个文件走到下一个、再走回 PR，全程不必碰侧边栏。YAML front matter 渲染成 一张安静的元数据表，而不是一堵加粗的文字墙——所以配置密集的文档也能干净地 比对。全新的文档读起来仍然是一份文档——一条说明写着它整篇都是新的，而不是把每个区块都染成 绿色。已有的审查会话出现在它们所讨论的区块下方。悬停任意区块，点开气泡，就能评论整个区块， 或者只评论你挑中的那几行。写完之后，直接在总览页上 Approve（批准）、Request Changes（请求更改）或 Comment（评论）——带不带行内评论都行——也可以留下文件级评论或纯粹的会话 评论。总览页显示这个 PR 的处境：已批准还是已请求更改、每位审查者的裁定、 CI 检查（可一路点进任意一项检查的日志），以及作为可读时间线呈现的完整会话。打开的 PR 每分钟检查一次；分支往前走了，一键刷新，你的草稿安然无恙。

Add to Review（加入审查）

默认动作：把草稿评论先攒在本地。再一起提交——Comment、Approve 或 Request Changes——也可以存成待完成的审查，回 github.com 上收尾。

Comment Now（立即评论）

立刻发出一条审查评论，锚在该区块上——也可以在编辑框里选行，把范围收窄到你挑中的 那几行。

Edit as Suggestion（编辑为建议）

铅笔把区块的 Markdown 源码在编辑器里打开——你的改动会作为一条 ```suggestion 发出去，作者一键即可应用。

阅读

给你硬盘里那些 Markdown，一个像样的阅读器。

你的笔记、你的 README、你们团队的 docs 文件夹——打开一个文件，或者整个 目录，按它本该有的样子读。文件在磁盘上一变，页面立刻重新渲染；相对路径的图片与链接自动 解析；只要 GitHub 渲染得出来，PullMark 就渲染得出来：

粗体、斜体、删除线、行内代码、 高亮、H2O、mc2、 eiπ + 1 = 0、 带悬停预览的链接、脚注[1]、 任务列表——还有表格、Mermaid 图表、 语法高亮的代码、> [!NOTE] 提示框、离线的 KaTeX 数学公式、 [toc]，以及折叠成一张整洁元数据表的 YAML front matter。

  • 历史留在页边——一条安静的 blame 边栏：每段连续区块一个头像；悬停 可见作者、日期和提交；点击可看完整的行历史。
  • 永远是最新的——在任何编辑器里保存，页面早已重新渲染完毕。
  • 与历史比对——一键把工作中的文件与最近的任意一次提交或任意分支 比较，像 PR 差异一样渲染出来；文件继续变，差异就继续跟； pullmark --diff 在终端里做同一件事——回答“智能体刚刚把我的文档改成 什么样了”最快的方式。
  • 浏览而不至于把自己埋了——在文件夹或仓库里单击，每个文件都以 预览出现：Open Files 里一条斜体条目，下次点击就被替换。双击（或者直接开始 编辑）就把它留下。
  • 大纲侧边栏——一张导航器式的标题地图，一个开关的距离。
  • 什么都找得到——⌘F 在页面上逐个走过匹配项； ⇧⌘F 一次搜遍侧边栏里的所有文件。
  • 会重排的缩放——⌘+ 与 ⌘−（或者双指捏合） 把文字、图片和阅读栏一起缩放，跨启动记住；导航也跟着一起长。
  • 点开细看——图片、Mermaid 图表和块级公式在可平移缩放的专注浮层中 打开，复杂图表不再被困在栏宽里——而且存储或共享的正是你正在细看的东西 （图表是真正的 SVG）。
  • 带它去任何地方——导出为 PDF，或一个完全自包含的 HTML 文件； ⌘C 粘进 Docs 和 Slack 是富文本，⌥⌘C 还你 Markdown。
  • 三套阅读主题——Editorial、GitHub 和 Terminal，在设置里带实时 预览——也可以丢进你自己的 CSS。浅色与深色会把一切重新配色，Mermaid 也不例外； 行宽归你：Standard、Wide 或 Full Width。
  • GitHub 链接在应用内打开——点击一个指向 Markdown 文件的 github.com 链接，PullMark 就渲染它，并始终显示一条 repo @ branch 的来源栏；⌘-点击则把它交给浏览器。
  • Open Quickly（快速打开）——⌘K 模糊匹配，跳到任意标题、 文件或 PR——也可以粘贴一个 PR 链接、仓库链接或文件路径，直接打开。
  • 搬了家就是搬了家——原样挪了位置的段落只渲染一次，佩戴一枚安静的 紫色标签，而不是红加绿的噪音。
  • 接着上次继续——你的文件、PR 和阅读位置在启动时一并恢复。

以上只是要点。剩下的都在文档里——每个功能、每项 设置、每个图标、完整的键位表，还有 pullmark 命令。

默认是读。编辑就在原地。

按下 ⌘E，页面本身就成了编辑器：光标所在的区块就地显出它的 Markdown 源码——同样的字体，同样的位置，什么都不跳——你立刻就能打字。用方向键在区块间 穿行，用 Backspace 合并，用一个空行拆开；离开某个区块就把它保存，走的是和别处一样有防护、 有版本记录的那条路。阅读依然是默认；模式的边界，就是保存这个动作。

GitHub 也是文档住的地方。就当住处来读它。

点击一个指向 Markdown 文件的 github.com 链接，PullMark 会抓取 它、在应用内渲染出来——第一次点击会问你想要哪种行为，而 ⌘-点击永远执行另一种。 页面上方的来源栏写明你正在读哪个仓库的哪个分支，并钉在它解析到的那次提交上；相对链接照旧 按仓库解析，整棵 Markdown 树在侧边栏里一点即达，私有仓库用的就是你的 PR 已经在用的 GitHub 登录——抓取到的东西从不落盘。分支是每个仓库上的一枚标签：就地切换、把另一个分支作为独立的 侧边栏条目打开，或者跳进本地工作树。而如果这个仓库已经克隆在你的 Mac 上、正停在那个分支， 链接打开的就是你的本地文件。

原生

一个真正像 Mac 应用的 Mac 应用。

Quick Look（快速查看）

在 Finder 里对任意 Markdown 文件按空格，还没打开任何应用，就已经用你的阅读主题 看到了它渲染后的样子。

一个真正的命令行

pullmark README.md、pullmark ~/wt docs/plan.md——文件、 文件夹和工作树都在正在运行的应用里打开，永远落在最前面的窗口。 pullmark --help 写着说明，文档也写着。

.md 的默认应用

在设置里点一下，Finder 里的双击从此处处意味着渲染——万一某次升级弄丢了 这条绑定，PullMark 会自己发现，并把它请回来。

你现成的凭据

不用另外登录。PullMark 直接用 gh auth token 或你的 git 凭据助手—— 私有仓库和组织仓库开箱即用。

硬盘上什么都不留

抓取到的 PR 内容只活在临时会话和有限的内存缓存里——来自 GitHub 的东西一律不写入 持久化存储。
