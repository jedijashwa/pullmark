文档

侧边栏

分区按事物的含义组织，而不是按 来源：你打开了什么、你固定的地方、你浏览的地方、与你相关的拉取 请求和议题，以及你去过哪里。

打开的文件

工作集：每一份你明确打开过的文档——来自 Finder、拖放、⌘O、 命令行，或从某个“位置”保留下来的文件。 平铺排列，可拖动排序，悬停任意一行出现 ✕ 即可移除（选中行按 ⌫ 亦可）。 右键分区标题有 全部关闭。

预览

在“位置”里单击一个文件，它立即渲染——并以预览的身份 出现在“打开的文件”中：一条斜体条目，始终排在分区最后。再点另一个文件， 预览条目就被替换，所以浏览一棵大树永远不会堆出一摞行。这与 VS Code 的 预览标签页或 Xcode 的临时编辑器是同一个思路，连斜体都一样。

当你对一份预览表现出阅读之外的投入，它就转正为普通的固定条目：

  • 双击树里的文件，或双击那条斜体条目本身
  • 开始编辑——进入“编辑模式”或保存一次 区块编辑都会把它固定
  • 右键菜单里的 保持打开

阅读性的动作——blame、行历史、细看图片或图表——刻意不会转正预览。 如果你更希望每次点击都完整打开文件，请在设置里改 点击“位置”中的文件。

远程仓库以同样的方式、在同样的位置预览。浏览 GitHub 仓库的文件树，或跟随远程文档内部的链接，会在“打开的文件”中放同一条 斜体条目——带书本图标和 owner/repo @ ref 的第二行，因为 文件不在你的 Mac 上。每个窗口永远只有一条预览，本地远程皆然： 预览任何新内容都会替换你之前预览的东西。保留一份远程文档（双击或 “保持打开”）才把它归档到它的仓库——它会移到“位置”中该仓库的固定 列表里。⌘K 打开的内容直接固定，因为粘贴 URL 是明确的意图。

凡是位于某个已打开“位置”内的“打开的文件”行，右键菜单里都有 在“位置”中显示——从“我在读什么” 跳回“它住在哪里”。

已固定

你反复回访的文件夹和文件，被放在“位置”上方——就像 Finder 把“个人收藏”放在最上面一样。在任意树中右键点击一个文件夹或文件， 选择固定…：文件夹会成为拥有自己那棵树的独立根， 文件会成为一行书签，单击即可预览；新条目会落在分区底部，并已处于 重命名状态。一个“位置”根会得到固定命令（它会 移动到这里），一个已固定的根会得到取消固定命令 （它会移动到“位置”底部，并保留原名）。

重命名的方式与 Finder 一致：选择 重命名…，或者在选中的行上按 Return；输入后按 Return、点击别处，或转向别处都会提交；Escape 取消；清空输入框会 恢复为真实名称。重命名过的条目会在名称下方以小字显示它的真实 路径，任何一对同名的根也是如此，因此两个都叫 docs 的文件夹绝不会看起来一样。固定的条目属于偏好设置，而不是会话的 一部分：无论重新 打开上一次的会话如何设置，它们每次启动都会回来。

位置

可浏览的根，无论它们住在哪里。两种行共享这一分区，靠图标区分：

行含义
📁 文件夹图标本地文件夹——其中的 Markdown 文件以树呈现 （或平铺列表；右键 → 以列表显示）。持续监视变化。
📕 书本图标为浏览而打开的 GitHub 仓库——从 API 抓取， 不写盘。

本地文件夹若是 git 检出，会长出一枚分支标签 （分支符号 + 名称）；若其远端在 GitHub 上，还会出现一个小小的合上书本 标记——悬停可见对应哪个仓库。点击分支标签打开分支与工作树菜单：

  • 工作树——仓库的每个工作树，当前行 对应的那个打勾；选择另一个即作为独立的“位置”打开。PullMark 从不 检出或切换工作树——它只是打开已经在那里的文件夹。
  • 查看 GitHub 上的分支—— 远程读取另一个分支的文件，不动你的检出。已有本地工作树的分支会 跳到那个工作树——本地优先于远程。
  • 在 GitHub 上打开——在浏览器里 打开该仓库（当前分支）。

在远程（书本图标）仓库上，同一枚标签列出分支：切换到 把会话重新钉到另一个分支，按住 ⌥ 则出现 单独打开分支供并排阅读。 浏览仓库文件…载入仓库完整的 Markdown 树。仓库保留的文档排在树上方，永远不会淹没在大仓库里； 已在树中可见的保留文档就在树里表示。（仅在预览的文档显示在 “打开的文件”，不在这里。）

路径解析不了的文件夹（未挂载的卷、被删除的工作树）会变暗并带上 问号角标，而不是消失——路径回来时它自己复活。

拉取请求

每个打开的 PR 是一组：先是总览行（状态图标 + 改动的 Markdown 数量），然后是它改动的 Markdown 文件——带计数的评论气泡标记着有 未解决审查会话的文件。在你打开的 PR 之下，是与你相关的 拉取请求，分成几个分组：审查请求、 已创建、已分配和 参与中（你评论过、审查过，或被提及）。空分组保持 隐藏，草稿标注· 草稿，当分组本身说明不了原因时，某一行会 写明原因（· 已分配、· 已提及）。每个分组载入最近 更新的 30 条，并以显示更多…结尾。未读计数即使在 折叠的标题上也保持可见；这项功能整体可在 设置中关闭，也可 筛选为只显示涉及 Markdown 的 PR。

关注一个仓库即可看到其中所有打开的内容，按最新 排序：分区标题里的关注仓库…会提供你已经打开过的 仓库，也可以直接输入 owner/repo。被关注的仓库自成一组， 有自己的未读规则——右键点击它可选择全部、 仅我的或无，也可以 取消关注。任何单条 PR 或议题行都可以在自己的 右键菜单里覆盖这条规则。

更喜欢单一列表？把 GitHub 工作分组方式 设为参与方式，会把这个分区和“议题”合并成一个统一的 GitHub分区，其中的分组会把两种类型混在一起， 每一行都用一个图标加以区分。

PR 行的状态图标：

状态图标
草稿拉取请求箭头，灰色
开启拉取请求箭头，绿色
已合并合并箭头，紫色
已关闭✕ 圆圈，红色
不可用垃圾桶，灰色——PR（或你的访问权限）不在了

PR 内的逐文件标记：绿色 + 圆圈为新增，红色 − 圆圈为删除，→ 圆圈为重命名， 铅笔圆圈为修改。

议题

同样的思路也适用于议题——已创建、 已分配、参与中，以及所关注仓库的 议题——因为你被要求审查的文档常常是一个议题，而不是拉取请求。 点击一个议题，它会作为一篇文档打开：渲染后的正文、标签、带表情 回应的评论时间线，以及末尾的一个撰写框。无需离开应用即可评论、 回应表情，以及编辑或删除自己的评论。打开的议题会以单独一行停在 分区顶部，同时进入“最近使用”和 ⌘K 快速打开，并随会话一起恢复。

最近使用

最近打开、且没有在上方出现的文件、文件夹和拉取请求。PR 条目带着 实时状态图标；文件已丢失的最近条目会变暗（时钟角标）而不是消失， 路径回来时复活——为切换分支和未挂载的卷而生。右键分区标题可 清除最近使用。

移除

悬停任意顶层行出现 ✕——它把行从侧边栏移走，绝不删除磁盘或 GitHub 上的任何东西。选中行按 ⌫ 效果相同。“位置”树内的文件没有 ✕： 它们是一个地方的内容，不是侧边栏条目。

分支符号只出现在真正的 git 引用上（只作标签， 绝不作文件夹图标）——文件夹是文件夹，仓库是书本，分支是分支。
