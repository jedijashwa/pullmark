La barre latérale

Quatre sections, organisées selon ce que les choses signifient plutôt que leur provenance : ce que vous avez ouvert, les lieux que vous parcourez, les pull requests que vous révisez, et là où vous êtes passé.

Fichiers ouverts

Fichiers ouverts, c'est l'ensemble de travail : chaque document explicitement ouvert — depuis le Finder, par glisser-déposer, ⌘O, la ligne de commande, ou en gardant un fichier d'un emplacement. À plat, réordonnable en glissant, chaque ligne retirable avec le ✕ au survol (ou ⌫ sur la ligne sélectionnée). Clic droit sur l'en-tête de section pour Tout fermer.

Aperçus

Cliquez une fois un fichier dans un emplacement : il se rend immédiatement — et apparaît dans Fichiers ouverts en aperçu, une seule entrée en italique, toujours dernière de la section. Cliquez un autre fichier et l'entrée d'aperçu est remplacée : parcourir une grande arborescence n'empile jamais de lignes. C'est la même idée que les onglets d'aperçu de VS Code ou l'éditeur temporaire de Xcode, avec les mêmes italiques.

Un aperçu devient une entrée normale, épinglée, dès que vous lui montrez un engagement au-delà de la lecture :

  • Double-cliquez le fichier dans l'arborescence, ou l'entrée italique elle-même
  • Commencez à éditer — entrer en Mode édition ou enregistrer l'édition d'un bloc l'épingle
  • Garder ouvert dans le menu contextuel

Les interactions de lecture — blame, historique de lignes, inspection d'une image ou d'un diagramme — ne promeuvent délibérément jamais un aperçu. Si vous préférez que chaque clic ouvre pleinement les fichiers, basculez « Clic sur un fichier dans Emplacements » dans Réglages.

Les dépôts distants s'aperçoivent de la même façon, au même endroit. Parcourir l'arborescence d'un dépôt GitHub, ou suivre des liens dans un document distant, place la même entrée italique unique dans Fichiers ouverts — avec une icône de livre et une seconde ligne owner/repo @ ref, puisque le fichier n'est pas sur votre Mac. Il n'y a jamais qu'un seul aperçu par fenêtre, local ou distant : apercevoir quoi que ce soit remplace ce que vous aperceviez avant. Garder un document distant (double-clic ou Garder ouvert) est ce qui le classe avec son dépôt — il rejoint la liste épinglée du dépôt sous Emplacements. ⌘K ouvre directement épinglé, coller une URL étant une intention explicite.

Toute ligne de Fichiers ouverts qui vit dans un emplacement ouvert gagne Afficher dans Emplacements dans son menu contextuel — le saut retour de « ce que je lis » vers « là où ça vit ».

Emplacements

La section Emplacements regroupe les racines navigables, où qu'elles vivent. Deux espèces partagent la section, distinguées par l'icône :

LigneSignification
📁 icône dossierUn dossier local — ses fichiers Markdown en arborescence (ou en liste à plat ; clic droit → Afficher en liste). Surveillé pour les changements.
📕 icône livreUn dépôt GitHub ouvert pour la navigation — récupéré via l'API, rien n'est écrit sur le disque.

Un dossier local qui est une copie de travail git gagne une pastille de branche (glyphe de branche + nom) ; si son remote est sur GitHub, une petite marque de livre fermé apparaît aussi — survolez-la pour voir quel dépôt. Cliquer la pastille de branche ouvre le menu branches-et-worktrees :

  • Worktrees — chaque worktree du dépôt, avec une coche sur celui de cette ligne ; choisissez-en un autre pour l'ouvrir comme emplacement à part. Les worktrees ne sont jamais « checkout » ni basculés depuis PullMark — il ouvre le dossier qui est déjà là.
  • View Branch from GitHub (voir la branche depuis GitHub) — lisez les fichiers d'une autre branche à distance, sans toucher à votre copie locale. Une branche qui a déjà un worktree local saute vers le worktree — le local l'emporte sur le distant.
  • Ouvrir sur GitHub — le dépôt (à cette branche) dans votre navigateur.

Sur un dépôt distant (icône livre), la même pastille liste les branches : Switch To (basculer vers) ré-épingle la session sur une autre branche, et maintenir ⌥ propose Ouvrir la branche à part pour une lecture côte à côte. Parcourir les fichiers du dépôt… charge toute l'arborescence Markdown du dépôt. Les docs gardées du dépôt siègent au-dessus de l'arborescence, pour ne jamais se noyer sous un gros dépôt ; une doc gardée visible dans l'arborescence y est simplement représentée. (Une doc simplement en cours d'aperçu s'affiche dans Fichiers ouverts, pas ici.)

Un dossier dont le chemin cesse de se résoudre (volume démonté, worktree supprimé) s'estompe avec un badge point d'interrogation au lieu de disparaître — il ressuscite tout seul quand le chemin revient.

Pull Requests

Chaque PR ouverte est un groupe : la ligne de vue d'ensemble (icône d'état + nombre de fichiers Markdown modifiés), puis ses fichiers Markdown modifiés — une bulle avec compteur marque les fichiers aux fils de révision non résolus. Sous vos PR ouvertes, Demandes de révision rassemble les PR qui attendent votre révision, avec un compteur non lu qui reste visible même replié (masquable dans Réglages, et filtrable aux seules PR touchant du Markdown).

Icônes d'état sur les lignes de PR :

ÉtatIcône
Brouillonflèches de pull request, grises
Ouverteflèches de pull request, vertes
Fusionnéeflèches de fusion, violettes
Fermée✕ dans un cercle, rouge
Indisponiblecorbeille, grise — la PR (ou votre accès) a disparu

Marqueurs par fichier dans une PR : cercle + (vert) pour ajouté, cercle − (rouge) pour supprimé, cercle → pour renommé, cercle crayon pour modifié.

Récents

Récents : les fichiers, dossiers et pull requests récemment ouverts qui ne sont pas déjà visibles au-dessus. Les entrées de PR portent leur icône d'état en direct ; un récent dont le fichier a disparu s'estompe (badge horloge) au lieu de s'effacer, et ressuscite quand le chemin revient — pensé pour les changements de branche et les volumes démontés. Clic droit sur l'en-tête pour Effacer les récents.

Retirer des éléments

Survolez n'importe quelle ligne de premier niveau pour le ✕ — il retire la ligne de la barre latérale, jamais rien du disque ni de GitHub. ⌫ sur une ligne sélectionnée fait de même. Les fichiers dans l'arborescence d'un emplacement n'ont pas de ✕ : ce sont les contenus d'un lieu, pas des éléments de la barre latérale.

Glossaire des icônes

IcôneSignification
DocumentUn fichier Markdown
Document, nom en italiqueL'aperçu — remplacé par votre prochain simple clic
DossierUn dossier ou répertoire local
Dossier + ?Dossier introuvable pour l'instant — estompé, il ressuscitera
Document + horlogeUn fichier récent qui a disparu
Livre ferméUn dépôt GitHub (en icône de ligne : parcouru à distance ; en petite marque de fin de ligne : ce dossier local en est une copie de travail)
Glyphe de branche + nomLa pastille de branche — cliquez pour branches et worktrees
Flèches de pull requestUne pull request
Bac de réceptionDemandes de révision — les PR qui attendent votre révision
Bulle + compteurSur un fichier de PR : commentaires de révision non résolus. Sur une ligne de Fichiers ouverts : des notes de marge encore dans le document
Point coloré (bord gauche)Une demande de révision non lue
✕ dans un cercle (au survol)Retirer de la barre latérale / congédier l'aperçu

Le glyphe de branche n'apparaît que sur de vraies refs git (des pastilles, jamais comme icône de dossier) — un dossier est un dossier, un dépôt est un livre, une branche est une branche.
